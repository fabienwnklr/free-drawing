# CLAUDE.md

Guide for working on this repository: `@fabwcie/free-drawing`, an infinite canvas drawing library (TypeScript + [Konva](https://konvajs.org/)). Usage: `new Drawer($el, options)` + `import '@fabwcie/free-drawing/style.css'`. User documentation: [packages/free-drawing/README.md](packages/free-drawing/README.md), changelog: [packages/free-drawing/CHANGELOG.md](packages/free-drawing/CHANGELOG.md).

## Architecture

- **`Drawer`** ([src/Drawer.ts](packages/free-drawing/src/Drawer.ts)) is the public API (package entry: [src/index.ts](packages/free-drawing/src/index.ts), exports only: the drawer, types and classes of its API, API of plugins; build entry and alias of `@fabwcie/free-drawing` in the web app and the plugin template), extends `MicroEvent` (`on` / `off` / `trigger`). Listeners of the page (window, document, media queries) are added with `{ signal: drawer.signal }` and resize observers disconnected on its abort: `destroy()` (plugins destroyed, tool deactivated, collaboration left, signal aborted, stage destroyed, element emptied) removes them all (`tests/destroy.test.ts` checks every listener added). It builds a Konva `Stage` with 4 layers, in this order:
  - `bgLayer` (`background`, not listening): background `Rect` named `drawer-background`;
  - `gridLayer` (`grid`, not listening): one `Shape` with a `sceneFunc` drawing the visible grid;
  - `drawLayer` (named `' draw'`, with a leading space: select it with `.draw`): the drawing shapes;
  - `selectionLayer`: transformer, selection rectangle, snapping guides (transient, cleared on load).
- Constructor order matters: options → preferences and texts → layout (container) → saved stage or new stage → plugins created (`drawer.plugins._create`: their widgets and texts) → context menu, settings, zoom, undo / redo → `Toolbar` (widgets, also of plugins) → `Help` (reads toolbar widgets) → active tool → events → plugins initialized (`_init`) → read only → optional collaboration.
- **UI components** are plain DOM classes added to regions of [DrawerLayout](packages/free-drawing/src/DrawerLayout.ts) with `drawer.layout.add(region, $el, { hideInZen, after })`: `ContextMenu` (right click: shape under pointer selected, sections of items shown for selection or drawing, each with its shortcut, run once hidden; height limited to the drawer by `_moveTo`, scrolls; hidden with `display: none`: out of the layout, else taller than the drawer it makes the page scroll), `Settings` (dropdown: height limited to the space below it in the drawer and the window, `fitHeight` of utils/dom on show and resize, also used by the collaboration panel), `SaveButton` (header, `saveButton` option: shown while auto save is off, dot for unsaved changes; the web app uses its own button of app bar), `CollaborationIndicator` (header after the layers button, `collaboration` option: shown during a session, also in zen mode: live dot (blue while presenting) and people connected, number of requests to draw, opening [CollaborationPanel](packages/free-drawing/src/components/CollaborationPanel/CollaborationPanel.ts) (popover after the group of buttons, not in it: rights of the user, request button, presentation switch, requests to accept or refuse, participants, "Link and settings..." opening the dialog; Escape and clicks out of it close it, by the path of the click), "Follow" button shown while a presentation is not followed, red stop button (`stop.svg`, `$danger`) stopping (owner) or leaving it after a `ConfirmModal` (`confirmStop`, `setConfirmLabel` names the action; focus back on the drawer), updated on `drawer.collaboration.change`), `LayersPanel`, `SelectionMenu`, `LinkEditor`, `Zoom`, `Position`, `UndoRedo`, `Help` (modal), `CommandPalette` (modal), `PreferencesModal` (modal), `Toast` (no live role: its message is read by `drawer._announce` in a live region kept in the page, [utils/liveRegion](packages/free-drawing/src/utils/liveRegion.ts) `status` / `alert`, of the drawer or of the dialog shown: nothing out of an `aria-modal` dialog is read), `Modal` / `ConfirmModal` (each with its live region) (focus trap on the stops of Tab: `_getFocusables` skips hidden elements and negative tab indexes, one stop per radio group), overlays. Color choices use [ColorPicker](packages/free-drawing/src/components/ColorPicker/ColorPicker.ts) (palette, custom color input, optional transparent), colors are compared with `normalizeColor` ([utils/color](packages/free-drawing/src/utils/color.ts)). Background color (`fillColor`) only applies to `fillShapes` (rectangle, ellipse), transparent is no fill (`toFill`). Edges (`edges`: 'sharp', 'round' or radius number) only apply to `edgesShapes` (rectangles): `cornerRadius` from `getCornerRadius` ([utils/stroke](packages/free-drawing/src/utils/stroke.ts)), recomputed while drawing, read back with `getEdges` (radius of a shape, shown in radius field). Regions: `header` (top left: settings menu, layers button, position), `footerStart` (zoom, undo / redo), `footer` (toolbar, help), `floating` (menus, panels, overlays, dialogs, toasts, text editor: before footer while drawer is created, after it once `layout.ready()`, so panels come before footer in tab order). Konva empties the container when it creates the stage: `layout.setStage` puts canvas, header and footer back. Zen mode (`layout.setZen`, from `Settings.toggleZenMode`) hides elements added with `hideInZen` (`is-zen` class), `layout.setPointerEvents` sets `--drawer-pointer-events`, a drawer of window size follows the window (`is-full`: ResizeObserver of the document element, `overflow: hidden`: nothing out of it makes the page scroll). Compact interface (`is-compact`, `layout.updateCompact`: footer overflowing its width once the class is removed, checked on `ready`, stage `widthChange`, zen mode and footer elements added): toolbar on its own line scrolled in it (group menus hidden on scroll: capture listener on footer), header wraps, options panel below the header (`--drawer-header-height`, ResizeObserver of the header). `$drawerContainer`, `$headerContainer`, `$footerContainer`, `$footerLeftElement` and `UIPointerEvents` of previous versions are getters / wrappers of the layout. `Drawer._update()` runs after each view move or zoom (background, position).
- **Texts** ([src/i18n](packages/free-drawing/src/i18n/)): no hard-coded UI text, every text is `drawer.t(key, params)` (`{name}` placeholders). [en.ts](packages/free-drawing/src/i18n/en.ts) is the reference (`TranslationKey`), `fr`, `es`, `de` are typed `Translations` (a missing key fails type check, `tests/i18n.test.ts` checks placeholders). `drawer.i18n` is created first in the constructor (language: saved `<key>-language` choice, else `language` option, 'auto' = `getLanguage()` of browser), `translations` option overrides texts. Static texts are set with `drawer.i18n.translate((t) => ...)`: run at once and again by `setLanguage`. Content rebuilt from state (layers rows, collaboration dialog, help) re-renders on `drawer.language.change`, or calls `drawer.t` when rendered. Widget titles come from `tools.<id>` keys (unless `title` option). Details of errors in toasts (`{error}`) come from `getErrorText(error, t)` of [utils/errors](packages/free-drawing/src/utils/errors.ts): errors of the library are `DrawerError` (key of `error.*` text, message in English for developers), errors of the browser translated by name (`QuotaExceededError`, `NotAllowedError`...), other messages kept (server, app).

### Widgets (toolbar tools)

- [BaseWidget](packages/free-drawing/src/components/toolbar/widgets/BaseWidget.ts) is the common base of all widgets: behavior shared by several widgets belongs there (or in an intermediate base such as `ShapeWidget`), not duplicated in each widget. It handles button, shortcut, options (`title`, `shortcut` from `options.widgets`) and lifecycle: `setActive(true)` deactivates the previous widget, then calls `initEvents()` → `updateCursor()` (stage cursor from the `cursor` property) → shows `overlay` (unless `showOverlayOnActive` is false, e.g. selection) → `onActive()` → `drawer._takeFocus()` (also on creation: focus without scrolling the page, not taken from another element of the page, a field or a dialog of the drawer); deactivation calls `removeEvents()` → hides `overlay` → `onDesactive()`. `showToolOverlay()` shows it again once the selection is cleared, only with `showOverlayOnActive` (the frame tool shares the overlay of shape tools without showing it).
- Pointer actions (drawing, erasing, selecting, panning) call `startAction()` on pointer down and `endAction()` on pointer up: `inAction` is read by `Drawer._duringAction()` (shortcuts disabled) and UI ignores pointer meanwhile. Konva listens to its canvas only: during an action, `_followPointer` sends window `mousemove` / `mouseup` out of the canvas to the stage as konva events at the pointer position (`setPointersPositions`), and ends the action on a mouse move without pressed button (released unseen) or a `touchcancel`; reset per-action state on pointer down, an action can end without pointer up (tool changed). `clearSelection()` unselects shapes from any widget.
- Register stage events with `this.onStage('mousedown touchstart', handler)`: they are namespaced with the widget id and removed on deactivation. One pointer at a time (`onStage` wrapper): during an action, `mousedown` / `touchstart` are ignored, a touch action follows its finger (`#touchId`): `touchend` of another finger ignored, its own one ends it at its position (konva points the first finger still on the screen). Two fingers on the canvas ([TouchGestures](packages/free-drawing/src/utils/TouchGestures.ts), `drawer.gestures`: listened on the konva content after konva, `targetTouches` only, `touch-action: none`): pinch zooms (`zoom` option) and moves the view, also in read only, without change fired; the second finger cancels the action (`cancelAction()`: `onCancel()` of the tool removes what it was drawing, then `endAction()`; drags stopped), the wrapper ignores touches while `gestures.active` (until every finger is lifted). Do not call `stage.on` / `stage.off` directly in widgets.
- [ShapeWidget](packages/free-drawing/src/components/toolbar/widgets/ShapeWidget.ts): drag-to-draw base (`line`, `square` → Rect, `circle` → Ellipse, `arrow`, `frame`; [PathShapeWidget](packages/free-drawing/src/components/toolbar/widgets/PathShapeWidget.ts): `triangle`, `diamond`, `heart`, `cloud`, `star`, `hexagon`, `blockArrow`, `bubble`, `checkbox` (its check mark an open subpath turning as the square: filled with it, not a hole) → Path of a box of size 1 scaled by `scalePath`, in `pathShapes` (fill, stroke style, inside by `isPointInPath`)), `onDrawEnd(shape)` then `placeInFrames`. [FreehandWidget](packages/free-drawing/src/components/toolbar/widgets/FreehandWidget.ts): perfect-freehand strokes of `brush` and `highlighter` (own colors and sizes in `HighlighterOverlay`, fill only with `multiply`: no stroke nor width set by selection). `laser`: `Trail` (glow) in selection layer, `collaboration.setLaser` adds `laser` to `POINTER` (trails of other users, color of their cursor), not disabled in read only. Default `widgetGroups` puts the path shapes and these 3 tools in "More tools" (menu of `groupColumns` (4) widgets per line, css grid columns from `--drawer-group-columns`; Up / Down move by a line). Implement `createShape(start)` and `updateShape(shape, start, end, constrain)`; a press moved less than `clickTolerance` (screen px, also of the selection) draws nothing; shift constrains (square, circle, 45°), also pressed or released during a pointer action (`BaseWidget.onConstrainChange`, used by brush for a straight stroke). With the selection, Shift keeps proportions (transformer `keepRatio` false, Konva keeps them with Shift; true for texts), rotates by 15° (Konva transformer, `shiftBehavior` 'default') and moves along an axis (`dragBoundFunc` set on drag start). One `ShapeOverlay` shared by shape tools.
- [Toolbar](packages/free-drawing/src/components/toolbar/Toolbar.ts) creates widgets from `options.widgets` (list or object of widget options) with the `widgetClasses` map, groups of `options.widgetGroups` at the place of their first widget ([GroupWidget](packages/free-drawing/src/components/toolbar/widgets/GroupWidget.ts): button with `getGroupIcon` icon showing its widgets in a `position: fixed` menu placed by `_place`, footer scrolls; created by code with widget instances, added by `toolbar.addGroup`). Widgets of groups stay in `toolbar.widgets` (shortcuts, help, palette, read only); toolbar arrow keys and tab stop use top buttons (`_getButtons`), `toolbar.getButton(widget)` gives the group button, `toolbar.update()` highlights / disables groups. `$keepToolButton` (pin, Q, only with the selection widget) is the first top button, before a separator: with `keepTool` false, `BaseWidget.afterDraw()` (end of a `ShapeWidget` / `FreehandWidget` drawing) activates the selection widget, nothing selected. Adding a widget: class + folder in `src/components/toolbar/widgets/` + `WidgetName` type + `widgetNames` ([constants](packages/free-drawing/src/constants.ts)) + `widgetClasses` + `tools.<id>` title in every language. `tests/basic.test.ts` compares widget folders count with toolbar widgets.

### Plugins

- [Plugin](packages/free-drawing/src/plugins/Plugin.ts) is the base of plugins of other developers (`plugins` option, classes with static `pluginName` and `requires`), [PluginCollection](packages/free-drawing/src/plugins/PluginCollection.ts) is `drawer.plugins`: `resolvePlugins` orders classes (required ones first, missing class requirements added, errors thrown for a missing name, duplicate names, cycles), `_create` before the toolbar (plugin constructors: `addWidget` registers in `plugins.widgets`, `addTranslations` calls `i18n.extend`), `_init` after `_initEvents` (`init` then `afterInit` of each plugin in order, synchronous until one returns a promise: `plugins.ready`, waited by `drawer.ready`; errors logged), then commands with `contextMenu` go to one section of the context menu (`contextMenu.addSection`) and help is rendered again (`help.refresh`). Commands (`addCommand`) are read on each use: palette (`_getPaletteCommands`, end of the editor group), `HotKey` (`_runShortcut` before the library shortcuts, not in fields, `matchesShortcut`), help. A command is available when its plugin is not force disabled, not in read only (unless `readOnly`) and `isAvailable`. Texts of plugins come after the library ones (`I18n.t`: custom, language, plugin language, English, plugin English), `I18n.has` gives widget titles (`tools.<id>`). Tool names are `AvailableTools` / `ToolbarWidgetName` (any string, names of the library suggested); plugin widgets not in the `widgets` option are added at the end. Options of plugins: given with the class in the `plugins` option (`PluginEntry`: class or `[class, options]`, kept by plugin name in `PluginCollection` before the plugins are created), read by `Plugin.getOptions(defaults)` (`plugins._getOptions`); the deprecated `pluginOptions` option (by plugin name, optional without default, warning) under them. `drawer.getPointerPosition()` is the public pointer in drawing coordinates for plugins and apps. Plugins draw with existing shape classes only (files, links and server accept `shapeClasses` / `groupClasses`). New API for plugins is exported by the entry (`src/index.ts`: `Plugin`, `BaseWidget`, `ShapeWidget`...): keep it stable, document it in the README Plugins section.

### Shapes, options, events

- Add drawing shapes only with `drawer.addShape(shape)` (draggable only with selection tool). Drawing shapes are konva shapes or groups (`DrawingShape`, `shapeName.group`): code reading shape attributes uses `getShapes(node)` ([utils/hit](packages/free-drawing/src/utils/hit.ts)) for shapes of groups. Shapes of groups have ids but are not draggable (moved with their group, except when selected alone with Ctrl+click or layers panel); a shape put in another parent by code (group, ungroup) takes `_isMovedAlone` as draggable state (selection tool, parent drawing or content of a frame); collaboration, history and files handle top nodes (`getShapeState` keeps children), a changed group is replaced by collaboration. Shapes are identified by names from `shapeName` ([constants](packages/free-drawing/src/constants.ts)), e.g. `shape.hasName(shapeName.text)`.
- Types are declared only in [src/@types](packages/free-drawing/src/@types) (types only, no values), one file per domain: `drawer` (options, preferences, styles, colors, `DrawingShape`), `collaboration` (session, socket, messages, `DrawingChange`), `file` (`DrawingFile`, `ShapeState`, export options), `i18n` (languages, translation keys, from `en` and `languages` with `typeof`), `shapes` (linked arrow ends), `toolbar` (widgets, tools, overlays, trail), `ui` (layout, dialogs, toasts, menus, palette, help, color picker), `utils` (listeners, throttled functions), `vite-env.d.ts`. No `type` / `interface` nor inline object type in other files: name it there. Buttons of a choice (palettes, widths, styles, edges, stacking orders, text options, themes) use `Choice<T>` (`value`, `label` key) and `IconChoice` / `TextChoice` / `ShortcutChoice`; stacking orders are `shapeOrders` ([constants](packages/free-drawing/src/constants.ts)), shared by panels and palette. Types used by apps are exported by the entry (`src/index.ts`: `DrawerOptions`, `DrawerStorage`, `Preferences`, `DrawingFile`...), also classes reachable from the public API as types (`export type { DrawerLayout }`...: members of the drawer, results of its methods): export new public types and classes there too (`index.d.ts` declares no class or type it does not export).
- Options: `DrawerOptions` ([src/@types/drawer.ts](packages/free-drawing/src/@types/drawer.ts)), defaults in `defaultOptions` ([src/constants.ts](packages/free-drawing/src/constants.ts)). Setters (`setStrokeColor`, `setStrokeWidth`, `setStrokeStyle`, `setEdges`, `setOpacity`, `setTextStyle`) update options, apply to the selection, then trigger `drawer.options.change` with the changed keys. Overlays ([BaseOverlay](packages/free-drawing/src/components/tools/Overlay/BaseOverlay.ts) and subclasses) listen to it to update their fields: overlay buttons only call setters.
- Style of shapes ([utils/style](packages/free-drawing/src/utils/style.ts) `getShapesStyle`: each part of `OptionsChange` from the first shape it applies to, shapes of groups too, color as `SelectWidget.setColor` gives it, width and dash from the first shape with a stroke; `getTextStyle`), read by `BaseOverlay.show` (over the options, frames: opacity only) and `drawer.copyStyle` (Ctrl + Alt + C, `copiedStyle`); `pasteStyle` calls the setters in `SelectWidget.batchUpdates` (one change: `_updateSelected` fires it at the end). Color pickers have an eyedropper with the EyeDropper API (`EyeDropperWindow` of @types/ui, button `$pickButton`): in a drawer in dark mode, the color picked is taken back by `fromDarkColor` (utils/color: inverse of the filter, its hue rotation of 180 degrees is its own inverse; colors clamped by the filter come back near them).
- Stroke styles are names (`strokeStyle`: solid, dashed, dotted): the dash is computed from stroke width with `getDash` ([utils/stroke](packages/free-drawing/src/utils/stroke.ts)) and recomputed when width changes, the style of a shape is read from its dash (`getStrokeStyle`).
- After any drawing modification, call `drawer.stage.fire('change')`: it saves to localStorage (`autoSave`, else marks changes unsaved: `hasUnsavedChanges`, `drawer.unsaved.change`, "Save now" of menu and palette, warning on page leave; only a successful save clears it (`_onSaved`): a failed one, a save of `storage` in progress or not loaded keep it), adds a history entry and triggers `drawer.change` event. Shape drags are listened on `drawLayer` (`dragend.change`): one change per drag, `Drawer._endDrag` (also from the `dragend` of the transformer) places the shapes in frames and fires it at the last `dragend` of the gesture (konva ends each node dragged: selected shapes, transformer; others still in `DD._dragElements` with status `stopped`).
- Konva listeners on layers are namespaced (`.grid`, `.snap`, `.change`, `.edit`) so they can be removed separately.
- Files and links ([utils/drawingFile](packages/free-drawing/src/utils/drawingFile.ts)): `.freedrawing` JSON (`DrawingFile`: background, shapes states), validated by `parseDrawingFile` (only drawing shape classes, frames with their 3 parts (`parseFrame`), attributes of `attrChecks` of their type, other attributes kept only when konva has no `set<Key>` method for them (data of plugins), `link` attributes of web pages and emails only, files and links come from anyone; shapes of collaboration changes too, by `parseShapeState`; a new attribute written by the library goes in `attrChecks`, the round trip test of `file.test.ts` checks every tool), `loadDrawing` creates all nodes before replacing the drawing, links put compressed drawing in hash `#drawing=` (`#<id>=` with the `id` option: `#linkKey`; the default id `drawer-<n>` depends on the drawers created before), loaded by `_loadFromLink` of one drawer (hash removed before decoding), `#drawer-<n>=` of previous versions too; a file or link opened is shown by `zoomToFit` (`showArea` with 100 % at most and a margin for the interface; not a drawing of `storage`).
- Texts of shapes ([utils/boundText](packages/free-drawing/src/utils/boundText.ts)): a `Text` with `containerId` (id of a rectangle, ellipse, path shape or arrow: `containerShapes`) is placed in its shape by `updateBoundTexts` (drag / transform `.binding` listeners with `updateBindings`, drawer change handler before saving): `placeBoundText` in coordinates of the parent of the text (transform of the shape), centered, width of the inside (rectangle 1, ellipse √½, path shapes 0.7) less `textPadding`, rotation of the shape, scale back to 1 (the transformer scales it during a resize), visible with its shape; arrow labels on the middle of the line, automatic width (`fontSize * 6` while empty), halo (`stroke` of the background, `fillAfterStrokeEnabled`; svg `paint-order`). A text whose shape is missing loses `containerId` (a free text: removing it in the change handler would add entries to history). `withBoundTexts` adds partners to selections (`SelectWidget.select`); `deleteShapes` and the eraser remove the texts of removed shapes (not the reverse); `duplicateShapes` remaps `containerId`; `findBindingTarget` skips texts of shapes. Text tool: a click, or a double click (listened by the stage: empty inside of a shape has no hit; texts of shapes with the selection tool only, a double tap of a drawing tool creates nothing) edits `_textAt` (text clicked, else text of the shape clicked or of the smallest one around the pointer: `findContainerAt`, created by `_createBoundText`, else a new free text). The listeners of presses out of the edited field are added by a timer: not once the edit ended (Enter typed at once: input events come before timers).
- Sticky notes ([utils/note](packages/free-drawing/src/utils/note.ts)): rectangles named `drawer-rect drawer-note` (`shapeName.note` before `rect` in `shapeLabels` and layer icons: notes are rectangles everywhere else: fill, corners, texts, arrows, hit, svg), `noteAttrs` (`noteSize` square, color of `noteColors`), shadow drawn by the `sceneFunc` of `setupNotes` (`_setupShape`, not saved; none on the hit canvas: `hitCanvas` of the context; light in a container of `.drawer-dark`, made dark by the filter; drawn again by `_applyTheme`; svg `noteShadowFilter`), `placeBoundText` grows a note for its text (`notePadding`, never shorter). [NoteWidget](packages/free-drawing/src/components/toolbar/widgets/Note/Note.ts) (N, its own color in [NoteOverlay](packages/free-drawing/src/components/tools/Overlay/NoteOverlay/NoteOverlay.ts), sections by `createOverlaySection` as `HighlighterOverlay`): a click on a note (or its text) writes in it, elsewhere `addNote` then `TextWidget.editTextOf(note, onEnd)` (`editTextNode` calls `onEnd` with the text, null when removed empty): `afterDraw`, note selected unless the tool is kept. `TextWidget.pressEndedEdit` (set by a press on the canvas ending any edit) is read and reset by the press of the text and note tools, reset when they are activated.
- Images ([utils/image](packages/free-drawing/src/utils/image.ts)): Konva `Image` named `shapeName.image` with a `fileId` attribute; its file (data URL: PNG, JPEG, WebP, GIF, `isImageData`; ids `[\w-]{1,64}`; `parseFiles` for anything read or received) is in `drawer.files` (`addFiles`), never in the node: `setupImages` (from `_setupShape`) gives the node its element (`#imageElements`, decoded once), a `toObject` without `image` (saves, history, collaboration: jsdom would serialize the element as `{}`) and a `sceneFunc` filtering it as the drawing in dark mode (redrawn by `_applyTheme`; exports draw it unfiltered: their stage is out of the drawer). `addImage(Blob | DrawingImage, position)` (`readImage`: 2048 px at most, WebP else PNG / JPEG; 60 % of the view at most; id: SHA-256 of the data, random without `crypto.subtle`), `insertImage(position)` (image tool of the toolbar: `ImageWidget`, `actionOnly` (its `setActive(true)` runs the action, never the active tool nor the first one of the drawer), no shortcut (plugins may use I); settings menu, context menu at the right click, palette), paste of image files (`HotKey`). Selected images: opacity, order, align and actions only (color and width setters skip them), transformer keeps their ratio. Svg export: `<image href>` of their element.
- Links of shapes (`link` attr of any drawing shape, group or frame, `setShapeLink` / `getShapeLink` / `openShapeLink`): web pages and emails only ([utils/link](packages/free-drawing/src/utils/link.ts) `parseLink`: `https://` added without protocol, checked again before opening), [LinkEditor](packages/free-drawing/src/components/LinkEditor/LinkEditor.ts) above the selection (shown for a link or by `edit()` from the panel, context menu and palette, placed after the selection menu and out of it, Enter / Escape prevent their default: focus goes back to the button that opened it), icons of [ShapeLinks](packages/free-drawing/src/utils/shapeLinks.ts) in the selection layer (placed again on each `draw` of the draw layer in view coordinates, created again once the selection layer is emptied, press not bubbled to the stage), `<a>` around shapes in svg exports.
- Export ([utils/export](packages/free-drawing/src/utils/export.ts), [ExportModal](packages/free-drawing/src/components/ExportModal/ExportModal.ts)): png and pdf are rendered by clones of shapes in an offscreen konva stage (`renderCanvas`, pixel ratio lowered to the canvas limits of browsers by `getCanvasScale`: else no image, e.g. Firefox; pdf page of the drawing size from the canvas scale), svg is written per shape class (`renderSvg`, konva has no svg export), pdf embeds a jpeg (`createPdf`), dark mode transforms colors (`toDarkColor`) so every format is the same. With `withDrawing` (switch of the dialog, not for copies), png and svg keep the drawing file of their shapes ([utils/embeddedDrawing](packages/free-drawing/src/utils/embeddedDrawing.ts): data of `encodeLinkData` in a `tEXt` chunk `free-drawing` before `IEND` (CRC-32 of its table) or `<metadata id="free-drawing">` after the opening `<svg>` tag); `drawer.open` reads `.freedrawing`, png and svg files with `readDrawingFile` (`error.noDrawingInImage` without drawing).
- Align, distribute, stack ([utils/align](packages/free-drawing/src/utils/align.ts)): `drawer.alignShapes(alignment)` (2 shapes), `distributeShapes(direction)` (3: first and last by center stay), `stackShapes(direction)` (2: first by start stays, `stackGap`), by boxes in the draw layer (bounding boxes of rotated shapes), nodes moved in layer coordinates whatever their parent (`moveBy`: `absolutePosition`), then `_arrangeShapes`: `unbindMoved`, `placeInFrames` (highlighted), change; choices `shapeAlignments`, `shapeDistributions`, `shapeStacks` ([constants](packages/free-drawing/src/constants.ts)) shared by the "Align" and "Distribute" sections of `BaseOverlay` (2 selected shapes, distribute buttons disabled under 3) and the palette. - Stacking order ([utils/order](packages/free-drawing/src/utils/order.ts)): `drawer.reorderShapes(order)` moves selected shapes (`forward` / `backward` past the next overlapping shape, `front` / `back`), from "Layers" buttons of `BaseOverlay` (shown only for a selection) and Ctrl+Up / Down. Collaboration sends `order` (all ids) in `CHANGE` when the order of known shapes changed (`#synced` keeps the stacking order), received ones are applied with `applyOrder`.
- Arrows ([utils/arrow](packages/free-drawing/src/utils/arrow.ts)): path `arrowType` attr (`curved`, `elbow`, none for straight ones) and heads `startHead` / `endHead` (`none`, `arrow`, `triangle`, `dot`, `bar`; konva pointers kept for the box, arrows of previous versions read from them by `getArrowheads`), from `arrowType` / `arrowheads` options (`drawer.setArrowType`, `setArrowheads`: new and selected arrows, sections of `BaseOverlay` shown by `toggleArrowBtns`). Heads are drawn by the `sceneFunc` set by `setupArrows` in `Drawer._setupShape` (not serialized: every arrow added or loaded goes through `addShape`), svg by `arrowheadSvg`. `routeArrow(arrow, start, end, boxes)` sets the points from the ends in coordinates of the arrow (`ArrowEnds` of `toArrowEnds` / `getArrowEnds`; `rerouteArrow` routes an arrow again on its links): curve through `curveMiddle` (`bend` attr: distance from the straight line in lengths of the arrow, positive on its left; `getDrawnBend` gives the side and size of the gesture while drawing), tension 0.5; elbow by [utils/elbow](packages/free-drawing/src/utils/elbow.ts) `getElbowPoints`: directions out of the sides (from the center of the box of the shape to the end), exits at `elbowDistance` (room for the heads) outside the grown boxes, cheapest path (length, turns, cost of the lines turned onto: middles between the ends and between the shapes free, others cost 1) on a sparse grid of lines (exits, borders of grown boxes, middles, outside) never inside a box nor going back (`searchGrid`), else `simpleElbow`; `elbowMid` (handle) is the place of the middle segment (`getMiddleSegment`) from the middle between the ends: its line is the only free one on its axis, taken only when a path uses it (`isOnLine`), forgotten by `routeArrow` when the middle segment turns the other way. Ends of elbow arrows without side leave the side facing the other end across the space between their boxes (`getBoundEnds` with `elbow`, boxes of linked shapes given). Called by `ArrowWidget.updateShape`, `updateBindings`, `SelectWidget.setArrowType` and [ArrowHandle](packages/free-drawing/src/utils/arrowHandle.ts) (`drawer.arrowHandle`: circle of the selection layer at `getHandlePoint`, for one curved or elbow arrow selected with its labels, selection tool, not locked nor read only; placed again on `drawer.selection.change` and each draw of the draw layer; Konva drag: `bend` from the distance to the straight line (snapped to 0), `elbowMid` along the axis of the middle segment at drag start (snapped to the automatic place), labels and live collaboration followed, change fired on drag end).
- Linked arrows ([utils/binding](packages/free-drawing/src/utils/binding.ts)): arrows have `startBinding` / `endBinding` attrs (ids of shapes, also of groups) and `startAnchor` / `endAnchor` (side whose middle the end is fixed to, else end on outline aiming at the other end). `ArrowWidget` links ends near a shape (smallest one, `findBindingTarget` with shapes of frames and `bindingMargin` / zoom: rectangles, ellipses and path shapes by `getOutlineDistance` (path shapes: distance to their sampled outline, inside by even-odd) within the margin outside, inside with a background or within 2 margins (as their hit region), frames only near their border, other shapes by box; side with `getAnchorAt`, tolerance on screen too) and highlights them with their sides (also on hover); `updateBindings` puts linked ends on sides or outlines (`getAnchorPoints`, `getOutlinePoint`: rectangles, ellipses and path shapes as drawn, other shapes by box; outline of a path shape sampled by `getPathRings` from its `dataArray`, cached by data, its farthest crossing from the center: sides of path shapes are where the way from the center to the middle of a side of their box crosses it) on drag / transform and first in drawer change handler (before saving), removing links to missing shapes; `unbindMoved` unlinks arrows moved without their shapes (drag start, transform start, arrow keys).
- [History](packages/free-drawing/src/components/tools/UndoRedo/History.ts): `entries` are changes of this user (`HistoryEntry`: JSON before / after of each top shape added, changed or removed, Konva `toObject` without `draggable`; ids of drawing shapes before / after when shapes are removed, added or reordered; `background` before / after when the background color changed, e.g. file opened: put back with `Drawer._setBackground`, no change fired), found on each drawer `change` by comparing the drawing with the last recorded one (`#known`), `historyLimit` (100) states kept. Shapes applied by collaboration (`Collaboration._apply`) call `ignoreChanges` (`ignoreBackground` for a background of other users): their state becomes the known one, so undo / redo never revert changes of other users. Undo / redo put back only the shapes of the entry (`Node.create` + `addShape`, replaced at their index, removed ones above the nearest shape below them in the stored order), skip shapes changed by this user then removed by others, and drop entries left without effect. `appHistory` / `appHistoryStep` are deprecated getters of previous versions.
- Persistence: full stage JSON in localStorage (`options.localStorageKey`, tool in `<key>-tool`). `_loadSavedStage` ignores invalid data; on load the grid layer is rebuilt and the selection layer cleared. Keep loading compatible with saves of previous versions. With `storage` option (`DrawerStorage`, storage of an app), the stage is not read from localStorage: `loadFromStorage` (on init: `ready`) loads its drawing file and resets history, `save` calls `storage.save` (one at a time, `#saveAgain`, changes unsaved until the last one resolves), never before the drawing is loaded (`#storageLoaded`; nothing stored: drawing kept, saved with auto save). Link and room of the URL are opened after it (`_openFromUrl`).
- App integration: `user` option / `setUser` (id and name of collaboration sessions, else kept in browser), preferences (`getPreferences` / `setPreferences`: theme, language, grid, snapping, zen, autoSave, keepTool): read on init by `_readPreferences` (`<key>-preferences` JSON, then `<key>-theme` / `<key>-language` of previous versions, first valid value), code changing one calls `_preferencesChanged()`: saved at once in `<key>-preferences` (not while drawer is created), one `drawer.preferences.change` event per microtask, only if values changed. [PreferencesModal](packages/free-drawing/src/components/PreferencesModal/PreferencesModal.ts) (menu, Ctrl+,, command palette) applies its fields together with Save (`save()`: one `setPreferences` and `setUserName`, Cancel / Escape / close discard them), fields follow that event until changed. A new preference: `Preferences` type, `getPreferences` / `setPreferences` / `_readPreferences`, a field of the dialog, `toPreferences` of the server. Option objects replacing a non object default (`collaboration`, `storage`, `user`) are kept as given by `deepMerge` (class instances keep their methods).
- Drawer events ([MicroEvent](packages/free-drawing/src/utils/MicroEvent.ts) `on` / `off` / `trigger`) are named `drawer.<subject>.<action>`, names in `drawerEvents` ([constants](packages/free-drawing/src/constants.ts)). Names of previous versions (`deprecatedEvents`: `change`, `fd.*`) are mapped to current ones with a warning: keep them working.
- [HotKey](packages/free-drawing/src/utils/HotKey.ts): keydown on `$drawerContainer`; tool shortcuts come from widgets (letter without Shift: Shift + H / V flip, Shift + R / L rotate); `mod = ctrlKey || metaKey`; letters are read with `keyLetter` (also by `matchesShortcut` of plugins): letter typed in lowercase (Caps Lock, Shift, any Latin layout), with Option of macOS (changing characters) the letter of the physical key on the layout (Keyboard API of Chromium or letters typed without Alt), keyboard of another alphabet: QWERTY place, never with AltGr (Ctrl + Alt types characters); a shortcut without Shift checks `!e.shiftKey` (letters are lowercase); Shift + 1 / 2 / 0 (`e.code` `Digit<n>`: Shift types digits on AZERTY) zoom to fit the drawing (`zoomToFit`, 100 % at most), to the selection (`zoomToSelection`, 200 % at most) and to 100 % (center kept, as the zoom level button; back to origin: position widget), with `zoom` option, also in read only; Ctrl + S saves (`saveNow`), Ctrl + Shift + S downloads the file (`saveAs`), Ctrl + Y or Ctrl + Shift + Z redo, Alt shortcuts are not run in fields; nothing runs while `drawer._duringAction()`. Paste (text added to the drawing) is listened on `document` (out of editable elements Chromium fires it on the body), handled only with focus in the drawer and out of fields (`input`, `textarea`, `select`, editable content keep their paste). A new action gets its shortcut here, in the context menu, the command palette and help. Shortcuts are written in English (`Ctrl+Shift+Up`, `Delete`, `Ctrl+Click`: words `Delete`, `Arrows`, `Click`, `Space`, `Wheel` translated) and shown by `formatShortcut(shortcut, t)` of [utils/shortcut](packages/free-drawing/src/utils/shortcut.ts) (symbols of Apple keyboards on its devices, `isApple`: ⇧⌘Z, Ctrl being Cmd there, so a shortcut shown with Ctrl takes `metaKey` too), `aria-keyshortcuts` by `ariaShortcut` (Meta on Apple devices): never write them by hand.
- Flip (`flipShapes`): top nodes mirrored around center of selection (`x` / `y`, `scaleX` / `scaleY`, `rotation` negated, in parent coordinates), texts mirrored again around their own center (readable); rotation (`rotateShapes(angle)`): top nodes turned around center of selection in parent coordinates (other way in a flipped parent), positions rounded; copy as image (`copyImage`): `exportImage` result in `ClipboardItem` (promise for Safari), svg also as text.
- End-to-end encryption of collaboration ([utils/encryption](packages/free-drawing/src/utils/encryption.ts)): a new room gets a key (`createRoomKey`: AES-GCM 128 bits, base64url, unless `collaboration.encrypt` is false), put in its links (`&key=`, `getCollaborationLink`, page URL; read by `_openFromUrl`, given to `startCollaboration` / the dialog); `RoomCipher` (`Collaboration.cipher`, null in clear: links without key, previous versions) encrypts each shape (`{ id, data }`: id in clear for the server), files (under random ids), background (`encryptChange` / `decryptChange`: parts of another key or under another id dropped), pointers and views (`{ data }`, checked once decrypted: `checkPointer`); `keyCheck` (SHA-256 of the key) in `JOIN`: the server refuses another proof (`REJECTED` `key`, `_stopWith`), `ROOM` `encrypted` (missing: server of previous versions, session stopped). Encryption is asynchronous: in an encrypted room every message sent or received goes through `_inOrder` (one queue: at once when empty, so rooms in clear stay synchronous), `send` finds the change when its turn comes, a message encrypted during a lost connection is not sent (`#connection`), nothing runs once stopped. Needs Web Crypto (secure pages: `error.insecurePage`).
- Collaboration (`collaboration` option gives the server, sessions started from the menu dialog [CollaborationModal](packages/free-drawing/src/components/CollaborationModal/CollaborationModal.ts), `startCollaboration` or a `#room=<id>&by=<user id>` link): `socket.io-client` and `uqr` (QR code) are loaded with a dynamic import and externalized by the build. Clients `JOIN` a room (server keeps each room drawing, sends `USERS`). Pointers (`POINTER`) and shapes being drawn (`sendLive`, from `BaseWidget.shareLive` and drags / transforms, `CHANGE` with `live`) are sent every 50 ms at most as volatile messages, live changes are applied at once without history (the server keeps them in the drawing of the room: a shape discarded after its preview was sent, e.g. simple click of a shape tool, is removed for everyone by `discardLive`, `#sentLive`); cursors of other users are groups of the selection layer. New participants view only by default (`newUsersCanEdit` false for new rooms): a viewer asks to draw (`REQUEST`, `requestEdit`, once until answered, kept by the server for an owner joining later), the owner answers it (`answerRequest`: accepted gives the right, refusal sent back); joined as viewer, a toast tells how to ask (`_onCollaborationRight(canEdit, joined)`). The owner presents its view (`present`: `VIEW` with `drawer.getViewArea()`, sent from `Drawer._update` through `onViewChange` and on resize, at live interval; server keeps it for users joining meanwhile, null when the owner leaves): others follow it (`showArea`, fitted to their size, `#showingView` so it is not taken for a move of theirs) until they move theirs (`following` false), `follow()` again. Rooms have an owner (secret `ownerKey` given by the creator, kept in localStorage: owner is the socket giving it, `socket.data.owner`, never the id sent; server keeps its hash) who gives or removes the right to draw (`RIGHTS`, `USERS` with `canEdit`) and chooses whether new users can draw (`ROOM` `{ newUsersCanEdit }`, sent by server on join, switch of the dialog: else ids new in the room are viewers, so a viewer gets no right by rejoining with a new id); an anonymous user can't take the id of the owner or of an account of the room; without it, the drawer is read only (`setReadOnly`: UI entry points modifying drawing are disabled, API methods still work). Only the owner sees the session in the dialog (link, QR code, users, stop; rows of users kept by id when not changed: [CollaborationMembers](packages/free-drawing/src/components/CollaborationMembers/CollaborationMembers.ts), shared with the panel, focus and live region), other users only their name (a link asks it first: joined, the dialog closes, toast). Links and page URL carry the id of the user sharing them (`by`, sent as `invitedBy` on `JOIN`), the server resolves it to a name in `USERS`. [Collaboration](packages/free-drawing/src/components/Collaboration/Collaboration.ts) sends, on each drawer `change`, the shapes changed since last sync (`CHANGE` event: `{ upsert, remove }`, shapes identified by their `id`, given by `addShape`) and the background color when changed (`#syncedBackground`: null on first join, reset before `JOIN`, so a joining user takes the background of the room from the `full` change; a room without one gets theirs; changed here while disconnected: kept by `_merge`; the server keeps it with the drawing; viewers can't choose it: settings disabled in read only) and merges received ones; received during a pointer action, they are applied when it ends (`_onActionEnd`). Nothing is sent while disconnected or before the drawing of the room is received again (`#connected`, `#rejoining`); on reconnection, the whole drawing of the room (`CHANGE` with `full`, sent by server on each `JOIN`, also empty) is merged with changes made meanwhile (`_merge`: shapes changed here kept and sent, others from the room, shapes removed by others removed; empty room: whole drawing sent again). Socket event names come from `@free-drawing/protocol`. The server identifies logged in users by their account (id sent by client ignored) and sends `JOINED` (`{ userId }`) to the joining user: `Collaboration.userId` takes it (owner, rights, `getCollaborationLink`). The server ([apps/server/src/collaboration.ts](apps/server/src/collaboration.ts)) relays changes and keeps the drawing for clients connecting later (in memory, dropped when the room is empty); owner, rights and settings of rooms are saved in the `room` table (`saveRoom`, writes queued in order, read on start by `attachCollaboration`, rooms unused for `roomLifetime` forgotten), so an empty room or a restart gives nobody the room. Server checks a whole `CHANGE` before applying it (`checkChange`: ids, drawing shape classes `shapeClasses` / `groupClasses` of the protocol, also used by `parseShape` of the library), relays checked fields only, limits rooms (`limits`) and messages per event (`rates`, `socket.use`), refuses with `REJECTED` (`full`: session stopped by client, `too-big`: toast). Messages are at most `maxMessageSize` of the protocol (`maxHttpBufferSize` of the server, a bigger one closes the connection): the library checks each change (`_fits`, UTF-8 bytes counted near the limit) and does not send a bigger one (toast too big, shapes not marked synced: sent once it fits, kept by a merge); `Collaboration.maxMessageSize` lowered by tests. Undo / redo fire `change` too.

## Conventions

- TypeScript strict. Files of `src/` are imported with the `@/` alias, never relative paths (ESLint `no-restricted-imports`), also in tests and SCSS `@use` (`@use '@/scss/variables' as *`). Prettier (root `.prettierrc`): single quotes, 120 columns, 2 spaces, line endings kept (`endOfLine: auto`). Short English comments. Callbacks of `forEach` return nothing, prefer `for...of` (ESLint `array-callback-return` with `checkForEach`). Imports used as types only are `import type` (inline `type` for mixed ones, ESLint `consistent-type-imports`), strings built with template literals. [biome.json](biome.json) aligns Biome of the editor with these conventions (linter only: Prettier formats, non-null assertions and `any` allowed as by ESLint, imports not sorted): keep it free of diagnostics. Tests do not print: expected warnings are spied (`vi.spyOn(console, 'warn')`) and checked.
- JSDoc (checked by `yarn lint` on `src`, eslint-plugin-jsdoc): every class, function, method, constructor, getter and setter has a block with a description, `@param name description` for each parameter (not destructured ones), `@returns description` when a value is returned, no `{Type}` (types come from TypeScript). Properties, types and constants have a one line `/** ... */` (TypeDoc).
- Konva 10 (ES modules) is a peer dependency imported by subpath (`konva/lib/...`); the build externalizes `konva`, `perfect-freehand` and `socket.io-client`. Konva types `getAttr` / `setAttr` per class: not callable on `DrawingShape` (union), use a `Node` (`const node: Node = shape`) or `shape.attrs` (tests).
- Accessibility: create buttons with `createButton` (`type="button"`), name icon buttons with `setLabel` and update toggle buttons with `setPressed` (`active` class + `aria-pressed`, or `aria-checked` for menu items), on / off options of dialogs are switches (`createSwitch`: checkbox with role `switch`, styled by the `switch` mixin for every `input[role='switch']`), from [utils/dom](packages/free-drawing/src/utils/dom.ts). Lists of buttons use `arrowNavigation` (toolbar, context menu): arrows of the other orientation are not propagated either (no drawer shortcut from an item, e.g. arrows moving the selection). `HotKey` listens keydown on `$drawerContainer`: keys handled by a component (menu, dialog) must not propagate to it. A menu or dialog hidden gives focus back to the drawer (or its opener) unless an element out of the drawer took it (`hasFocusOutside` of utils/dom: field of the page or another drawer clicked; the context menu only when focus was in it). Enter / Escape of a field validating or closing it are ignored during a composition of an input method (`isComposing` of utils/dom: also key code 229 of Safari). New icons need `aria-hidden="true" focusable="false"`.
- Styles: one SCSS file per component, every rule scoped under `.drawer-container` (nothing applies to the host page). Color tokens are CSS custom properties (`--drawer-*`) set on the container from `$themes` (light, dark with `drawer-dark` class, see `Drawer.setTheme`): never use Sass color functions on tokens, add a value to both themes. Dark mode only filters the drawing (`$dark-drawing-filter` on `.konvajs-content` and the text editor), colors of shapes are kept; color swatches use `--swatch-color` / `--swatch-dark-color` (custom color input too). `color-scheme` follows the theme of the drawer, not of the page. Use tokens of [_variables.scss](packages/free-drawing/src/scss/_variables.scss) (colors, radius, shadows, spaces, font sizes) and mixins of [_mixins.scss](packages/free-drawing/src/scss/_mixins.scss) (`focus-ring`, `surface`, `menu-item`, `swatch`, `picker`, `button-group`, `switch`) with `@use`, not hard-coded values. An element whose rule sets `display` needs a `&[hidden] { display: none; }` rule to be hidden with `hidden` (done in `menu-item`). Panels receiving pointer use `pointer-events: var(--drawer-pointer-events)` (ignored during pointer actions).
- Icons are SVG files imported with `?raw`. In library mode vite inlines assets in `style.css` (the Ubuntu font is woff2 for that reason).
- Tests: use [tests/helpers.ts](packages/free-drawing/tests/helpers.ts) (`createDrawer` with an isolated localStorage key and no autosave, `keydown`, `fireMouse`, `drag`). jsdom has no hit canvas (mock `stage.getIntersection`), no layout and no `document.fonts`: check rendering, pointer and font behavior in a real browser.
- Working copy files use CRLF (`core.autocrlf=true`).

## Versioning and commits

- Each commit changing the library for its users adds its entry at the top of `packages/free-drawing/CHANGELOG.md` (`## [X.Y.Z](compare link) (date)` then `### Features` / `### Bug Fixes`...), copies it to `docs/changelog.md` (`yarn doc:changelog`) and bumps `version` in `packages/free-drawing/package.json` (major for breaking changes, minor for features, patch otherwise). Each version gets an annotated tag `vX.Y.Z`. Private packages (`@free-drawing/*`) have no changelog.
- Documentation and development changes (docs, CLAUDE.md, tests, tooling, refactoring without visible change) have no changelog entry and no version bump.
- `@fabwcie/create-free-drawing-plugin` has its own version and [CHANGELOG](packages/create-plugin/CHANGELOG.md) (same rules, no tag of its own): the `npm-packages` job of the release workflow (matrix: `create-plugin`, `react`, `vue`, `element`) publishes it with a release of the library once its version is not on npm yet (nor lower than the published one), trusted publisher of this package on npmjs.com like the library (scoped: `publishConfig.access` public; set less than 2 days before the release of its next version, a new one expires without a publish). Its first version is published by hand: `prepack` copies the template, and a tarball packed on Windows is packed from a copy with LF line endings (a CRLF shebang breaks the command with Yarn 1 on macOS / Linux), then published with `npm publish <tarball>`.
- `@fabwcie/free-drawing-react`, `@fabwcie/free-drawing-vue` and `@fabwcie/free-drawing-element` too: own version and CHANGELOG (`packages/react`, `packages/vue`, `packages/element`; a change of a component bumps its version, not the one of the library), published by the same job. Their first version is published by hand (`yarn build`, then `npm publish` in the folder of the package), then their trusted publisher is set on npmjs.com: until then the job publishes nothing for them (notice).
- `yarn release` pushes `master` with tags (no bump): the release workflow publishes the version on npm.
- Tags reach GitHub only when pushed: `git push --follow-tags` (or `git config push.followTags true`), a plain `git push` does not send them. A pushed tag `v*` runs the [release workflow](.github/workflows/release.yml): GitHub release with the changelog entry of the version and the compare link of its title (previous tag to this one), failed without entry, then npm publication (`npm` job: trusted publishing set in the package settings on npmjs.com: GitHub Actions, repository `fabienwnklr/free-drawing`, workflow `release.yml`, no environment, allowed actions with `npm publish` (trusted publishers created after 2026-09-03 allow only `npm stage publish`: 403 "OIDC permission denied for this action" although the token exchange succeeds; a new one expires without a publish within 2 days); no token nor `registry-url`: a missing or wrong trusted publisher fails with an authentication error or that 403, then [npm-oidc-check.mjs](.github/scripts/npm-oidc-check.mjs) prints the claims of the GitHub token, the answer of the npm token exchange and what to change on npmjs.com (error annotation); tested and built; only the highest version, not published yet, tag equal to `version` of `package.json`, whose `repository.url` must stay the GitHub repository). A push of more than 3 tags triggers no workflow: run it from the Actions tab with the tag, or `all` (releases of tags without one, oldest first, highest version "Latest"). Tags pushed together run at once: a package of the same version in two of them is published by one run, npm answers the other one 409 "Cannot publish over previously staged version" (npm still checks it, `npm view` does not show it yet): the publish steps take it as published (`set -o pipefail`: the default shell of a step is `bash -e`, the status of `npm publish | tee` would be the one of `tee`). A run uses the workflow of its tagged commit.
- Claude: never commit or push. Prepare the code, changelog entry, docs copy and version bump, then propose a short conventional commit message without co-author trailer. Tag versions (`git tag -a vX.Y.Z <commit> -m "vX.Y.Z"`) once the maintainer has committed them.

## Pitfalls

- Server: `node:sqlite` is loaded with `process.getBuiltinModule` (the vite 4 of previous tests did not know this built-in module) by `loadSqlite`, which drops its experimental warning, Kysely 0.29 migrations are imported from `kysely/migration`. TypeScript 5.9: binary data typed `Uint8Array<ArrayBuffer>` where a `BodyInit` / `BlobPart` is needed.
- Yarn 1 normalizes the `homepage` of every workspace manifest with `url.parse()`, deprecated by Node 24 (DEP0169 warning printed by each yarn command): no `homepage` in the `package.json` files of the repository (npm links the repository).
- `npx tsc` / `npx vitest` from a workspace folder in Git Bash resolve a wrong path: use `yarn workspace <name> <bin>`. Tools whose binary is run from the root (`typescript`, `prettier`, `vitepress`) are root dev dependencies, so the root `.bin` gets the right version. After a `yarn add`, Yarn 1 may link the root `.bin/tsc` to an older TypeScript of a dependency: `yarn install --force` links it back (check `node_modules/.bin/tsc`). ESLint 10 with a flat config (`eslint.config.js` of the library: `typescript-eslint`, `eslint-plugin-jsdoc` 63, the last one accepting Node 24.14).
- Tests run in one shared jsdom document (Vitest 5: `pool: 'forks'`, `maxWorkers: 1`, `isolate: false`, `clearMocks: false` as Vitest 0.34; also the plugin template): close dialogs opened by a test (a shown `Modal` listens keydown on document). A dialog whose drawer left the page releases its document listeners. Window and document listeners of drawers of previous tests still run (e.g. `mouseup` dispatched on `window`, whose target is not a node): an error thrown there is an "Unhandled Error" that fails `yarn test` (and the pre-push hook) although every test passes: check its exit code, not only the count of tests passed. Drawers of `createDrawer` are destroyed after each test file (`afterAll` of `vitest.setup.ts`, `drawers` of helpers: memory, listeners of the page); the memory of this process still grows with the tests (about 2 GB), its heap is raised to 8 GB (`execArgv` of `test` in `vite.config.ts`); "Child process exited unexpectedly with code 134" is a heap out of memory.
- Fonts load when first used: measure or draw texts after `document.fonts.load` (see `TextWidget._loadFonts`); exports wait for the fonts of their texts (`getFontsToLoad` / `loadFonts` of utils/text: canvas font of each text, `_getContextFont`), the export preview is drawn again once they are loaded (a canvas drawn before uses a serif fallback font). Konva 10 places lines like CSS (font box centered in line height, alphabetic baseline): the editing textarea is at the text position, svg export puts baselines at `lineHeight / 2 + (ascent - descent) / 2` (`measureSize('M')`), decorations at ±`round(fontSize / 4)`. Never set `Konva.legacyTextRendering` (global flag of the host app).
- Konva `Transformer` ends a transform on window `mouseup` (capture phase), before the stage `mouseup`: `isTransforming()` is already false there (see `#pressOnTransformer` in `SelectWidget`).
- Konva forgets the pointer when it leaves the canvas (`stage.getPointerPosition()` warns and gives null, e.g. on a menu item): read it with `drawer._getPointerPos` / `_getRelativePointerPos` (center of view without pointer, `_hasPointer`), keep a position needed later (context menu keeps the place of its right click for "Paste").
- Konva prevents default of mouse down on its canvas: a click does not move focus. `$stageContainer` pointer down focuses the drawer when focus is out of it (`_initKeyboardFocus`), so its shortcuts work after the page (bar of an app) was used. Ctrl + A keeps its default only in text fields (`textInputTypes` of `HotKey`), elsewhere it would select the text of the page.
- Grid: one stroke per line. A single path with hundreds of dashed lines is very slow in Chromium.
- `deepMerge` does not merge arrays: `widgets` option is replaced, not merged. Never mutate `defaultOptions` (setters replace nested objects such as `textStyle`).
- `GroupWidget` (group of toolbar widgets) is unrelated to groups of shapes (`groupShapes`).
- Frames ([utils/frame](packages/free-drawing/src/utils/frame.ts)): `Frame` class (registered in Konva: `Node.create`, files, collaboration), a `Group` of its box (hit on border only: `fillEnabled` false), title and content group (clip) holding its shapes; `getClientRect` is its box (not title nor cut shapes). Any `instanceof Group` check of groups of shapes must exclude frames (`isFrame`). Shapes of frames are drawing shapes (`withFrameShapes`, `getDrawingShape` stops at frame content, draggable, not `#nested`); `placeInFrames` (draw end, drag end, transform end, arrow keys, duplicate) moves them by center and returns the frames entered and left (`FrameChanges`), `fitFrame` on frame drawn or resized; while shapes are dragged or transformed (`Drawer._startMove` on drag / transform start, `_endMove` by `placeInFrames`) shapes of frames stay in them but are drawn above the drawing, not cut (`drawAbove`: own `drawScene` doing nothing, drawn on draw layer `draw.moved` event; never move them to another container meanwhile: saves, history, collaboration and changes received during a drag, which is not a pointer action, read the drawing), frames entered and left are highlighted by `drawer.frameHighlight` ([FrameHighlight](packages/free-drawing/src/utils/frameHighlight.ts): rectangles of selection layer, faded on drop, `flash` after arrow keys); transformer resizes frames (`setFrameSize`, shapes moved back); arrows link to shapes of frames. Exports hide titles, svg clips.
