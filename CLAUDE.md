# CLAUDE.md

Guide for working on this repository: `@fabwcie/free-drawing`, an infinite canvas drawing library (TypeScript + [Konva](https://konvajs.org/)). Usage: `new Drawer($el, options)` + `import '@fabwcie/free-drawing/style.css'`. User documentation: [packages/free-drawing/README.md](packages/free-drawing/README.md), changelog: [packages/free-drawing/CHANGELOG.md](packages/free-drawing/CHANGELOG.md).

## Repository

Yarn 1 workspaces (root `package.json` is private, `yarn.lock` at root):

- [packages/free-drawing](packages/free-drawing): the library published on npm (`src/`, `tests/`, its vite / vitest / tsconfig / eslint configs, README, CHANGELOG, LICENCE copy). Paths below without a folder are in it (`src/...`, `tests/...`).
- [packages/protocol](packages/protocol) (`@free-drawing/protocol`, private): socket events of live collaboration (`socketEvents`, JS + `index.d.ts`), imported by the library (bundled in its build, dev dependency) and the server.
- [apps/server](apps/server) (`@free-drawing/server`, [README](apps/server/README.md)): TypeScript run with tsx (`src/index.ts`, `createServer` in `src/app.ts` for tests). Express 4: Better Auth accounts (email + password, session cookie, changes of name, email and password, deletion with password only, `passwordToDelete` hook: drawings and preferences removed by foreign keys) under `/api/auth` (`src/auth.ts`), API of logged in users `/api/me`, `/api/preferences`, `/api/drawings` (`src/api.ts`, own drawings only, 404 for others), socket.io rooms (`src/collaboration.ts`), web app (`serveWeb`: vite middleware sharing the HTTP server for HMR in development, `apps/web/dist` in production). SQLite of Node (`node:sqlite`) with Kysely (`src/db.ts`): Better Auth tables migrated by its `getMigrations` before creating it, app tables (`drawing`, `preferences`, `room`) by a Kysely `Migrator` (add a migration, never change one). Settings from environment (`src/config.ts`). Tests: vitest + supertest on an in-memory database.
- [apps/web](apps/web) (`@free-drawing/web`): web app, its vite config (and tsconfig `paths`) aliases `@fabwcie/free-drawing` and `@/` to library sources. `App` (`src/App.ts`) adds an app bar (drawing name, save state, auto save switch: `drawer.setAutoSave`, "My drawings", account) above the drawer and a `storage` adapter of the drawing open in `app.store` (`DrawingsStore`: list, create, get, update, delete): drawings of logged in user on server (`api`, `src/api.ts`), else of browser (`localDrawings`, `src/local.ts`: summaries and contents in localStorage, never a drawing of an account; first one takes the drawing kept by previous versions or the demo). Served by the server (metas `api-server`, `collaboration-server` injected in its page, also in production): accounts and collaboration; without these metas (`yarn dev`, static site deployed by Netlify): drawings of browser only, no account button. Switching drawing (`_open`), login and logout: `drawer.save()` first, then `loadFromStorage()` right after changing `drawing` (a change in between would be saved in the new drawing), account preferences applied after loading (grid and snapping fire changes), preferences of anonymous users saved in browser by the drawer. Account button opens `AccountDialog` (sign in / up) or, logged in, `ProfileDialog` (name, email: compared with `/api/me` after change, password, sign out, account deleted with password then `_leaveAccount` like logout). Dialogs are native `<dialog>` (`AccountDialog`, `ProfileDialog`, `DrawingsDialog`), errors of server explained by `texts.error`, texts in `src/texts.ts` follow `drawer.language`, colors follow `drawer.isDarkMode()`.
- [docs](docs): VitePress site, built and deployed by Netlify on each push to `master` ([docs/netlify.toml](docs/netlify.toml): site with package directory `docs`, free-drawing-docs.netlify.app; no `netlify.toml` at the root, it would apply to every site). `yarn doc:changelog` / `doc:get-started` copy the library CHANGELOG, README and CONTRIBUTING into it (copies committed), `yarn doc:typedoc` generates the API of every source file of the library from its JSDoc, private and protected members included ([typedoc.json](packages/free-drawing/typedoc.json), TypeDoc + typedoc-plugin-markdown + typedoc-vitepress-theme) in `docs/api`, not committed, with `typedoc-sidebar.json` read by `docs/.vitepress/config.ts`. Every declaration (class, method, property, type and its properties, constant) has a JSDoc comment, also private ones: document new ones. README links are absolute (shown on npm and in the docs, VitePress fails on dead links). Logo: [docs/public/logo.svg](docs/public/logo.svg) (pencil drawing a stroke on a tile of the primary color, copied in `apps/web/logo.svg` for the app bar and favicon), `favicon.ico` of docs and web app hold PNG images of 16, 32 and 48 px rendered from it. Update the docs when a change needs it: run these scripts, then `yarn docs:build`.

## Architecture

- **`Drawer`** ([src/Drawer.ts](packages/free-drawing/src/Drawer.ts)) is the entry point and public API, extends `MicroEvent` (`on` / `off` / `trigger`). It builds a Konva `Stage` with 4 layers, in this order:
  - `bgLayer` (`background`, not listening): background `Rect` named `drawer-background`;
  - `gridLayer` (`grid`, not listening): one `Shape` with a `sceneFunc` drawing the visible grid;
  - `drawLayer` (named `' draw'`, with a leading space: select it with `.draw`): the drawing shapes;
  - `selectionLayer`: transformer, selection rectangle, snapping guides (transient, cleared on load).
- Constructor order matters: options → preferences and texts → layout (container) → saved stage or new stage → context menu, settings, zoom, undo / redo → `Toolbar` (widgets) → `Help` (reads toolbar widgets) → active tool → events → optional collaboration.
- **UI components** are plain DOM classes added to regions of [DrawerLayout](packages/free-drawing/src/DrawerLayout.ts) with `drawer.layout.add(region, $el, { hideInZen, after })`: `ContextMenu` (right click: shape under pointer selected, sections of items shown for selection or drawing, each with its shortcut, run once hidden), `Settings` (dropdown), `SaveButton` (header, `saveButton` option: shown while auto save is off, dot for unsaved changes; the web app uses its own button of app bar), `LayersPanel`, `SelectionMenu`, `Zoom`, `Position`, `UndoRedo`, `Help` (modal), `CommandPalette` (modal), `PreferencesModal` (modal), `Toast`, `Modal` / `ConfirmModal`, overlays. Color choices use [ColorPicker](packages/free-drawing/src/components/ColorPicker/ColorPicker.ts) (palette, custom color input, optional transparent), colors are compared with `normalizeColor` ([utils/color](packages/free-drawing/src/utils/color.ts)). Background color (`fillColor`) only applies to `fillShapes` (rectangle, ellipse), transparent is no fill (`toFill`). Edges (`edges`: 'sharp', 'round' or radius number) only apply to `edgesShapes` (rectangles): `cornerRadius` from `getCornerRadius` ([utils/stroke](packages/free-drawing/src/utils/stroke.ts)), recomputed while drawing, read back with `getEdges` (radius of a shape, shown in radius field). Regions: `header` (top left: settings menu, layers button, position), `footerStart` (zoom, undo / redo), `footer` (toolbar, help), `floating` (menus, panels, overlays, dialogs, toasts, text editor: before footer while drawer is created, after it once `layout.ready()`, so panels come before footer in tab order). Konva empties the container when it creates the stage: `layout.setStage` puts canvas, header and footer back. Zen mode (`layout.setZen`, from `Settings.toggleZenMode`) hides elements added with `hideInZen` (`is-zen` class), `layout.setPointerEvents` sets `--drawer-pointer-events`, a drawer of window size follows the window (`is-full`). `$drawerContainer`, `$headerContainer`, `$footerContainer`, `$footerLeftElement` and `UIPointerEvents` of previous versions are getters / wrappers of the layout. `Drawer._update()` runs after each view move or zoom (background, position).
- **Texts** ([src/i18n](packages/free-drawing/src/i18n/)): no hard-coded UI text, every text is `drawer.t(key, params)` (`{name}` placeholders). [en.ts](packages/free-drawing/src/i18n/en.ts) is the reference (`TranslationKey`), `fr`, `es`, `de` are typed `Translations` (a missing key fails type check, `tests/i18n.test.ts` checks placeholders). `drawer.i18n` is created first in the constructor (language: saved `<key>-language` choice, else `language` option, 'auto' = `getLanguage()` of browser), `translations` option overrides texts. Static texts are set with `drawer.i18n.translate((t) => ...)`: run at once and again by `setLanguage`. Content rebuilt from state (layers rows, collaboration dialog, help) re-renders on `drawer.language.change`, or calls `drawer.t` when rendered. Widget titles come from `tools.<id>` keys (unless `title` option).

### Widgets (toolbar tools)

- [BaseWidget](packages/free-drawing/src/components/toolbar/widgets/BaseWidget.ts) is the common base of all widgets: behavior shared by several widgets belongs there (or in an intermediate base such as `ShapeWidget`), not duplicated in each widget. It handles button, shortcut, options (`title`, `shortcut` from `options.widgets`) and lifecycle: `setActive(true)` deactivates the previous widget, then calls `initEvents()` → `updateCursor()` (stage cursor from the `cursor` property) → shows `overlay` (unless `showOverlayOnActive` is false, e.g. selection) → `onActive()`; deactivation calls `removeEvents()` → hides `overlay` → `onDesactive()`.
- Pointer actions (drawing, erasing, selecting, panning) call `startAction()` on pointer down and `endAction()` on pointer up: `inAction` is read by `Drawer._duringAction()` (shortcuts disabled) and UI ignores pointer meanwhile. `clearSelection()` unselects shapes from any widget.
- Register stage events with `this.onStage('mousedown touchstart', handler)`: they are namespaced with the widget id and removed on deactivation. Do not call `stage.on` / `stage.off` directly in widgets.
- [ShapeWidget](packages/free-drawing/src/components/toolbar/widgets/ShapeWidget.ts): drag-to-draw base (`line`, `square` → Rect, `circle` → Ellipse, `arrow`, `frame`; [PathShapeWidget](packages/free-drawing/src/components/toolbar/widgets/PathShapeWidget.ts): `triangle`, `diamond`, `heart`, `cloud` → Path of a box of size 1 scaled by `scalePath`, in `pathShapes` (fill, stroke style, inside by `isPointInPath`)), `onDrawEnd(shape)` then `placeInFrames`. [FreehandWidget](packages/free-drawing/src/components/toolbar/widgets/FreehandWidget.ts): perfect-freehand strokes of `brush` and `highlighter` (own colors and sizes in `HighlighterOverlay`, fill only with `multiply`: no stroke nor width set by selection). `laser`: `Trail` (glow) in selection layer, `collaboration.setLaser` adds `laser` to `POINTER` (trails of other users, color of their cursor), not disabled in read only. Default `widgetGroups` puts these 7 tools in "More tools". Implement `createShape(start)` and `updateShape(shape, start, end, constrain)`; shift constrains (square, circle, 45°), also pressed or released during a pointer action (`BaseWidget.onConstrainChange`, used by brush for a straight stroke). With the selection, Shift keeps proportions (transformer `keepRatio` false, Konva keeps them with Shift; true for texts), rotates by 15° (Konva transformer, `shiftBehavior` 'default') and moves along an axis (`dragBoundFunc` set on drag start). One `ShapeOverlay` shared by shape tools.
- [Toolbar](packages/free-drawing/src/components/toolbar/Toolbar.ts) creates widgets from `options.widgets` (list or object of widget options) with the `widgetClasses` map, groups of `options.widgetGroups` at the place of their first widget ([GroupWidget](packages/free-drawing/src/components/toolbar/widgets/GroupWidget.ts): button with `getGroupIcon` icon showing its widgets in a `position: fixed` menu placed by `_place`, footer scrolls; created by code with widget instances, added by `toolbar.addGroup`). Widgets of groups stay in `toolbar.widgets` (shortcuts, help, palette, read only); toolbar arrow keys and tab stop use top buttons (`_getButtons`), `toolbar.getButton(widget)` gives the group button, `toolbar.update()` highlights / disables groups. `$keepToolButton` (pin, Q, only with the selection widget) is the first top button, before a separator: with `keepTool` false, `BaseWidget.afterDraw()` (end of a `ShapeWidget` / `FreehandWidget` drawing) activates the selection widget, nothing selected. Adding a widget: class + folder in `src/components/toolbar/widgets/` + `WidgetName` type + `widgetNames` ([constants](packages/free-drawing/src/constants.ts)) + `widgetClasses` + `tools.<id>` title in every language. `tests/basic.test.ts` compares widget folders count with toolbar widgets.
- [SelectWidget](packages/free-drawing/src/components/toolbar/widgets/Select/Select.ts) owns the Konva `Transformer` (others use `getWidget<SelectWidget>('selection')?.transformer`, the widget may be disabled), the selection overlay (`showOverlay`: sections of every kind of selected shape, `SelectOverlay` extends `TextOverlay` for text fields, `toggle*Btns` / `toggleTextFields`, text panel for texts only; `hideOverlay`, `clearSelection`), setters applying styles to selected shapes (`_updateSelected`), snapping (drag: `dragmove.snap`; resize: transformer `anchorDragBoundFunc` → `_boundAnchor`, objects first, then `gridAnchorBound` set by drawer while grid is shown), text anchors (side anchors resize text width, corners scale). Selection: `select(shapes)`; a click selects the konva hit shape, or the smallest rectangle / ellipse without background around pointer (`getShapesAt`, Shift toggles, Alt cycles behind); the selection rectangle selects shapes it touches (`isTouchedBy` of [utils/hit](packages/free-drawing/src/utils/hit.ts): lines along their points, other shapes along their transformed box, groups by their shapes, frames by their box with `rectTouches`; a rectangle entirely inside a shape does not select it); a press in the selection box out of shapes drags the selection (`startDrag`).
- Hit regions are as drawn ([utils/hit](packages/free-drawing/src/utils/hit.ts) `setupHit`, applied by `addShape` and on load): rectangles and ellipses without background are hit on their outline only (hit function, not serialized, kept by collaboration updates). [EraserWidget](packages/free-drawing/src/components/toolbar/widgets/Eraser/Eraser.ts) looks for shapes along the pointer path from pointer down (`drawLayer.getIntersection` every 4 px), fades them (opacity, restored by `onDesactive`) and destroys them on pointer up; right and middle buttons ignored (also by the text tool click).
- [LayersPanel](packages/free-drawing/src/components/LayersPanel/LayersPanel.ts) (`layersPanel` option, button after settings menu, Alt+L): rows of shapes top first, rebuilt on `drawer.change` (deferred during rename or drag), highlighted on `drawer.selection.change` (triggered by `SelectWidget.select` / `clearSelection`), roving tab index per row. Rows select shapes (`_select`): alone, Ctrl / Cmd + click or Ctrl + Space adds or removes, Shift + click or Shift + arrows selects a range from `#anchor` (last row selected alone or added, or shape selected alone on canvas) among shapes of the same parent; shortcuts shown under the list (`$hint`, describes rows) and in help. Shapes have a `label` attr (name), hidden is `visible(false)`, locked is `listening(false)` (no konva hit): `select` ignores hidden shapes, selects locked ones only without other shapes and as a whole (top locked group, `getLockedNode`) to unlock them. A locked selection (`SelectWidget.isLocked()`: dashed box, no anchors, no overlay) is not modified by UI entry points (shortcuts, menus, palette, options), only unlocked; `getShapesAt` gives locked shapes after the others (`isDrawnAtLocked`: konva draws hits of listening nodes only).
- [SelectionMenu](packages/free-drawing/src/components/SelectionMenu/SelectionMenu.ts): actions next to selection (`selectionMenu` option), updated on selection layer `draw` (selection changed or moved, zoom...) and on drag / transform end, hidden during actions, drags, transforms and text edition. Placed out of the transformer client rect (`_getPlace`: box, resize and rotation anchors wherever rotation puts them): below, else above, right, left, in view above footer. Select shapes from code with `SelectWidget.select(shapes)`.
- [CommandPalette](packages/free-drawing/src/components/CommandPalette/CommandPalette.ts) (`commandPalette` option, menu item, Ctrl+K): combobox search field (focus stays in it, `aria-activedescendant`) and listbox of commands built on each opening by `_getCommands` (only available ones: read only, selection, history, components shown; `checked` for toggles, current tool and language). A new user command (menu item, shortcut) is added there too, with English words in `id` (searched with the translated label).
- [TextWidget](packages/free-drawing/src/components/toolbar/widgets/Text/Text.ts): text nodes, textarea editing (`editTextNode`), double click listened on `drawLayer` (any text is editable), font preload. Texts of a selection (`getTexts`: also of groups, not titles of frames) are fitted to their content by `drawer.fitTextWidth` ([utils/text](packages/free-drawing/src/utils/text.ts): width of a text of automatic width with the same attrs, moved along its x axis for center / right alignment).

### Shapes, options, events

- Add drawing shapes only with `drawer.addShape(shape)` (draggable only with selection tool). Drawing shapes are konva shapes or groups (`DrawingShape`, `shapeName.group`): code reading shape attributes uses `getShapes(node)` ([utils/hit](packages/free-drawing/src/utils/hit.ts)) for shapes of groups. Shapes of groups have ids but are not draggable (moved with their group, except when selected alone with Ctrl+click or layers panel); collaboration, history and files handle top nodes (`getShapeState` keeps children), a changed group is replaced by collaboration. Shapes are identified by names from `shapeName` ([constants](packages/free-drawing/src/constants.ts)), e.g. `shape.hasName(shapeName.text)`.
- Types used by apps are exported by the entry (`Drawer.ts`: `DrawerOptions`, `DrawerStorage`, `Preferences`, `DrawingFile`...): export new public types there too.
- Options: `DrawerOptions` ([src/@types/drawer.ts](packages/free-drawing/src/@types/drawer.ts)), defaults in `defaultOptions` ([src/constants.ts](packages/free-drawing/src/constants.ts)). Setters (`setStrokeColor`, `setStrokeWidth`, `setStrokeStyle`, `setEdges`, `setOpacity`, `setTextStyle`) update options, apply to the selection, then trigger `drawer.options.change` with the changed keys. Overlays ([BaseOverlay](packages/free-drawing/src/components/tools/Overlay/BaseOverlay.ts) and subclasses) listen to it to update their fields: overlay buttons only call setters.
- Stroke styles are names (`strokeStyle`: solid, dashed, dotted): the dash is computed from stroke width with `getDash` ([utils/stroke](packages/free-drawing/src/utils/stroke.ts)) and recomputed when width changes, the style of a shape is read from its dash (`getStrokeStyle`).
- After any drawing modification, call `drawer.stage.fire('change')`: it saves to localStorage (`autoSave`, else marks changes unsaved: `hasUnsavedChanges`, `drawer.unsaved.change`, "Save now" of menu and palette, warning on page leave, `save` clears it), adds a history state and triggers `drawer.change` event. Shape drags are listened on `drawLayer` (`dragend.change`).
- Konva listeners on layers are namespaced (`.grid`, `.snap`, `.change`, `.edit`) so they can be removed separately.
- Files and links ([utils/drawingFile](packages/free-drawing/src/utils/drawingFile.ts)): `.freedrawing` JSON (`DrawingFile`: background, shapes states), validated by `parseDrawingFile` (only drawing shape classes, files and links come from anyone; shapes of collaboration changes too, by `parseShapeState`), links put compressed drawing in hash `#<drawer id>=` (loaded by `_loadFromLink`).
- Export ([utils/export](packages/free-drawing/src/utils/export.ts), [ExportModal](packages/free-drawing/src/components/ExportModal/ExportModal.ts)): png and pdf are rendered by clones of shapes in an offscreen konva stage (`renderCanvas`), svg is written per shape class (`renderSvg`, konva has no svg export), pdf embeds a jpeg (`createPdf`), dark mode transforms colors (`toDarkColor`) so every format is the same.
- Stacking order ([utils/order](packages/free-drawing/src/utils/order.ts)): `drawer.reorderShapes(order)` moves selected shapes (`forward` / `backward` past the next overlapping shape, `front` / `back`), from "Layers" buttons of `BaseOverlay` (shown only for a selection) and Ctrl+Up / Down. Collaboration sends `order` (all ids) in `CHANGE` when the order of known shapes changed (`#synced` keeps the stacking order), received ones are applied with `applyOrder`.
- Linked arrows ([utils/binding](packages/free-drawing/src/utils/binding.ts)): arrows have `startBinding` / `endBinding` attrs (ids of shapes, also of groups) and `startAnchor` / `endAnchor` (side whose middle the end is fixed to, else end on outline aiming at the other end). `ArrowWidget` links ends near a shape (smallest one, `findBindingTarget`, side with `getAnchorAt`) and highlights them with their sides (also on hover); `updateBindings` puts linked ends on sides or outlines (`getAnchorPoints`, `getOutlinePoint`: rectangles and ellipses as drawn, other shapes by box) on drag / transform and first in drawer change handler (before saving), removing links to missing shapes; `unbindMoved` unlinks arrows moved without their shapes (drag start, transform start, arrow keys).
- [History](packages/free-drawing/src/components/tools/UndoRedo/History.ts): states are JSON strings of drawing shapes (Konva `toObject`, without `draggable`), identical states are skipped, `historyLimit` (100) states are kept, restore uses `Node.create` + `addShape`.
- Persistence: full stage JSON in localStorage (`options.localStorageKey`, tool in `<key>-tool`). `_loadSavedStage` ignores invalid data; on load the grid layer is rebuilt and the selection layer cleared. Keep loading compatible with saves of previous versions. With `storage` option (`DrawerStorage`, storage of an app), the stage is not read from localStorage: `loadFromStorage` (on init: `ready`) loads its drawing file and resets history, `save` calls `storage.save` (one at a time, `#saveAgain`), never before the drawing is loaded (`#storageLoaded`). Link and room of the URL are opened after it (`_openFromUrl`).
- App integration: `user` option / `setUser` (id and name of collaboration sessions, else kept in browser), preferences (`getPreferences` / `setPreferences`: theme, language, grid, snapping, zen, autoSave, keepTool): read on init by `_readPreferences` (`<key>-preferences` JSON, then `<key>-theme` / `<key>-language` of previous versions, first valid value), code changing one calls `_preferencesChanged()`: saved at once in `<key>-preferences` (not while drawer is created), one `drawer.preferences.change` event per microtask, only if values changed. [PreferencesModal](packages/free-drawing/src/components/PreferencesModal/PreferencesModal.ts) (menu, Ctrl+,, command palette) applies its fields together with Save (`save()`: one `setPreferences` and `setUserName`, Cancel / Escape / close discard them), fields follow that event until changed. A new preference: `Preferences` type, `getPreferences` / `setPreferences` / `_readPreferences`, a field of the dialog, `toPreferences` of the server. Option objects replacing a non object default (`collaboration`, `storage`, `user`) are kept as given by `deepMerge` (class instances keep their methods).
- Drawer events ([MicroEvent](packages/free-drawing/src/utils/MicroEvent.ts) `on` / `off` / `trigger`) are named `drawer.<subject>.<action>`, names in `drawerEvents` ([constants](packages/free-drawing/src/constants.ts)). Names of previous versions (`deprecatedEvents`: `change`, `fd.*`) are mapped to current ones with a warning: keep them working.
- [HotKey](packages/free-drawing/src/utils/HotKey.ts): keydown on `$drawerContainer`; tool shortcuts come from widgets (letter without Shift: Shift + H / V flip, Shift + R / L rotate); `mod = ctrlKey || metaKey`; shortcuts with Alt use `e.code` (Alt changes characters); nothing runs while `drawer._duringAction()`. A new action gets its shortcut here, in the context menu, the command palette and help.
- Flip (`flipShapes`): top nodes mirrored around center of selection (`x` / `y`, `scaleX` / `scaleY`, `rotation` negated, in parent coordinates), texts mirrored again around their own center (readable); rotation (`rotateShapes(angle)`): top nodes turned around center of selection in parent coordinates (other way in a flipped parent), positions rounded; copy as image (`copyImage`): `exportImage` result in `ClipboardItem` (promise for Safari), svg also as text.
- Collaboration (`collaboration` option gives the server, sessions started from the menu dialog [CollaborationModal](packages/free-drawing/src/components/CollaborationModal/CollaborationModal.ts), `startCollaboration` or a `#room=<id>&by=<user id>` link): `socket.io-client` and `uqr` (QR code) are loaded with a dynamic import and externalized by the build. Clients `JOIN` a room (server keeps each room drawing, sends `USERS`). Pointers (`POINTER`) and shapes being drawn (`sendLive`, from `BaseWidget.shareLive` and drags / transforms, `CHANGE` with `live`) are sent every 50 ms at most as volatile messages, live changes are applied at once without history; cursors of other users are groups of the selection layer. Rooms have an owner (secret `ownerKey` given by the creator, kept in localStorage: owner is the socket giving it, `socket.data.owner`, never the id sent; server keeps its hash) who gives or removes the right to draw (`RIGHTS`, `USERS` with `canEdit`) and chooses whether new users can draw (`ROOM` `{ newUsersCanEdit }`, sent by server on join, switch of the dialog: else ids new in the room are viewers, so a viewer gets no right by rejoining with a new id); an anonymous user can't take the id of the owner or of an account of the room; without it, the drawer is read only (`setReadOnly`: UI entry points modifying drawing are disabled, API methods still work). Only the owner sees the session in the dialog (link, QR code, users, stop), other users only their name. Links and page URL carry the id of the user sharing them (`by`, sent as `invitedBy` on `JOIN`), the server resolves it to a name in `USERS`. [Collaboration](packages/free-drawing/src/components/Collaboration/Collaboration.ts) sends, on each drawer `change`, the shapes changed since last sync (`CHANGE` event: `{ upsert, remove }`, shapes identified by their `id`, given by `addShape`) and merges received ones; received during a pointer action, they are applied when it ends (`_onActionEnd`). Socket event names come from `@free-drawing/protocol`. The server identifies logged in users by their account (id sent by client ignored) and sends `JOINED` (`{ userId }`) to the joining user: `Collaboration.userId` takes it (owner, rights, `getCollaborationLink`). The server ([apps/server/src/collaboration.ts](apps/server/src/collaboration.ts)) relays changes and keeps the drawing for clients connecting later (in memory, dropped when the room is empty); owner, rights and settings of rooms are saved in the `room` table (`saveRoom`, writes queued in order, read on start by `attachCollaboration`, rooms unused for `roomLifetime` forgotten), so an empty room or a restart gives nobody the room. Server checks a whole `CHANGE` before applying it (`checkChange`: ids, drawing shape classes `shapeClasses` / `groupClasses` of the protocol, also used by `parseShape` of the library), relays checked fields only, limits rooms (`limits`) and messages per event (`rates`, `socket.use`), refuses with `REJECTED` (`full`: session stopped by client, `too-big`: toast). Undo / redo fire `change` too.

## Conventions

- TypeScript strict. Files of `src/` are imported with the `@/` alias, never relative paths (ESLint `no-restricted-imports`), also in tests and SCSS `@use` (`@use '@/scss/variables' as *`). Prettier (root `.prettierrc`): single quotes, 120 columns, 2 spaces, line endings kept (`endOfLine: auto`). Short English comments. Callbacks of `forEach` return nothing, prefer `for...of` (ESLint `array-callback-return` with `checkForEach`, also flagged by Biome in the editor). Tests do not print: expected warnings are spied (`vi.spyOn(console, 'warn')`) and checked.
- JSDoc (checked by `yarn lint` on `src`, eslint-plugin-jsdoc): every class, function, method, constructor, getter and setter has a block with a description, `@param name description` for each parameter (not destructured ones), `@returns description` when a value is returned, no `{Type}` (types come from TypeScript). Properties, types and constants have a one line `/** ... */` (TypeDoc).
- Konva 10 (ES modules) is a peer dependency imported by subpath (`konva/lib/...`); the build externalizes `konva`, `perfect-freehand` and `socket.io-client`. Konva types `getAttr` / `setAttr` per class: not callable on `DrawingShape` (union), use a `Node` (`const node: Node = shape`) or `shape.attrs` (tests).
- Accessibility: create buttons with `createButton` (`type="button"`), name icon buttons with `setLabel` and update toggle buttons with `setPressed` (`active` class + `aria-pressed`, or `aria-checked` for menu items), on / off options of dialogs are switches (`createSwitch`: checkbox with role `switch`, styled by the `switch` mixin for every `input[role='switch']`), from [utils/dom](packages/free-drawing/src/utils/dom.ts). Lists of buttons use `arrowNavigation` (toolbar, context menu). `HotKey` listens keydown on `$drawerContainer`: keys handled by a component (menu, dialog) must not propagate to it. New icons need `aria-hidden="true" focusable="false"`.
- Styles: one SCSS file per component, every rule scoped under `.drawer-container` (nothing applies to the host page). Color tokens are CSS custom properties (`--drawer-*`) set on the container from `$themes` (light, dark with `drawer-dark` class, see `Drawer.setTheme`): never use Sass color functions on tokens, add a value to both themes. Dark mode only filters the drawing (`$dark-drawing-filter` on `.konvajs-content` and the text editor), colors of shapes are kept; color swatches use `--swatch-color` / `--swatch-dark-color`. Use tokens of [_variables.scss](packages/free-drawing/src/scss/_variables.scss) (colors, radius, shadows, spaces, font sizes) and mixins of [_mixins.scss](packages/free-drawing/src/scss/_mixins.scss) (`focus-ring`, `surface`, `menu-item`, `swatch`, `picker`, `button-group`, `switch`) with `@use`, not hard-coded values. An element whose rule sets `display` needs a `&[hidden] { display: none; }` rule to be hidden with `hidden` (done in `menu-item`). Panels receiving pointer use `pointer-events: var(--drawer-pointer-events)` (ignored during pointer actions).
- Icons are SVG files imported with `?raw`. In library mode vite inlines assets in `style.css` (the Ubuntu font is woff2 for that reason).
- Tests: use [tests/helpers.ts](packages/free-drawing/tests/helpers.ts) (`createDrawer` with an isolated localStorage key and no autosave, `keydown`, `fireMouse`, `drag`). jsdom has no hit canvas (mock `stage.getIntersection`), no layout and no `document.fonts`: check rendering, pointer and font behavior in a real browser.
- Working copy files use CRLF (`core.autocrlf=true`).

## Versioning and commits

- Each commit changing the library for its users adds its entry at the top of `packages/free-drawing/CHANGELOG.md` (`## [X.Y.Z](compare link) (date)` then `### Features` / `### Bug Fixes`...), copies it to `docs/changelog.md` (`yarn doc:changelog`) and bumps `version` in `packages/free-drawing/package.json` (major for breaking changes, minor for features, patch otherwise). Each version gets an annotated tag `vX.Y.Z`. Private packages (`@free-drawing/*`) have no changelog.
- Documentation and development changes (docs, CLAUDE.md, tests, tooling, refactoring without visible change) have no changelog entry and no version bump.
- `yarn release` pushes `master` with tags (no bump): the release workflow publishes the version on npm.
- Tags reach GitHub only when pushed: `git push --follow-tags` (or `git config push.followTags true`), a plain `git push` does not send them. A pushed tag `v*` runs the [release workflow](.github/workflows/release.yml): GitHub release with the changelog entry of the version and the compare link of its title (previous tag to this one), failed without entry, then npm publication (`npm` job: trusted publishing set in the package settings on npmjs.com: GitHub Actions, repository `fabienwnklr/free-drawing`, workflow `release.yml`, no environment; no token nor `registry-url`: a missing or wrong trusted publisher fails with an authentication error or a 403 "OIDC permission denied", then [npm-oidc-check.mjs](.github/scripts/npm-oidc-check.mjs) prints the claims of the GitHub token and the answer of the npm token exchange; tested and built; only the highest version, not published yet, tag equal to `version` of `package.json`, whose `repository.url` must stay the GitHub repository). A push of more than 3 tags triggers no workflow: run it from the Actions tab with the tag, or `all` (releases of tags without one, oldest first, highest version "Latest").
- Claude: never commit or push. Prepare the code, changelog entry, docs copy and version bump, then propose a short conventional commit message without co-author trailer. Tag versions (`git tag -a vX.Y.Z <commit> -m "vX.Y.Z"`) once the maintainer has committed them.

## Pitfalls

- Server: `node:sqlite` is loaded with `process.getBuiltinModule` (vite 4 of tests does not know this built-in module) by `loadSqlite`, which drops its experimental warning, Kysely 0.29 migrations are imported from `kysely/migration`. TypeScript 5.9: binary data typed `Uint8Array<ArrayBuffer>` where a `BodyInit` / `BlobPart` is needed.
- `npx tsc` / `npx vitest` from a workspace folder in Git Bash resolve a wrong path: use `yarn workspace <name> <bin>`. Tools whose binary is run from the root (`typescript`, `prettier`, `vitepress`) are root dev dependencies, so the root `.bin` gets the right version. After a `yarn add`, Yarn 1 may link the root `.bin/tsc` to the TypeScript 5.2 of commitlint: `yarn install --force` links it back (check `node_modules/.bin/tsc`).
- Tests run in one shared jsdom document (`threads: false`): close dialogs opened by a test (a shown `Modal` listens keydown on document). A dialog whose drawer left the page releases its document listeners.
- Fonts load when first used: measure or draw texts after `document.fonts.load` (see `TextWidget._loadFonts`). Konva 10 places lines like CSS (font box centered in line height, alphabetic baseline): the editing textarea is at the text position, svg export puts baselines at `lineHeight / 2 + (ascent - descent) / 2` (`measureSize('M')`), decorations at ±`round(fontSize / 4)`. Never set `Konva.legacyTextRendering` (global flag of the host app).
- Konva `Transformer` ends a transform on window `mouseup` (capture phase), before the stage `mouseup`: `isTransforming()` is already false there (see `#pressOnTransformer` in `SelectWidget`).
- Konva forgets the pointer when it leaves the canvas (`stage.getPointerPosition()` warns and gives null, e.g. on a menu item): read it with `drawer._getPointerPos` / `_getRelativePointerPos` (center of view without pointer, `_hasPointer`), keep a position needed later (context menu keeps the place of its right click for "Paste").
- Konva prevents default of mouse down on its canvas: a click does not move focus. `$stageContainer` pointer down focuses the drawer when focus is out of it (`_initKeyboardFocus`), so its shortcuts work after the page (bar of an app) was used. Ctrl + A keeps its default only in text fields (`textInputTypes` of `HotKey`), elsewhere it would select the text of the page.
- Grid: one stroke per line. A single path with hundreds of dashed lines is very slow in Chromium.
- `deepMerge` does not merge arrays: `widgets` option is replaced, not merged. Never mutate `defaultOptions` (setters replace nested objects such as `textStyle`).
- `GroupWidget` (group of toolbar widgets) is unrelated to groups of shapes (`groupShapes`).
- Frames ([utils/frame](packages/free-drawing/src/utils/frame.ts)): `Frame` class (registered in Konva: `Node.create`, files, collaboration), a `Group` of its box (hit on border only: `fillEnabled` false), title and content group (clip) holding its shapes; `getClientRect` is its box (not title nor cut shapes). Any `instanceof Group` check of groups of shapes must exclude frames (`isFrame`). Shapes of frames are drawing shapes (`withFrameShapes`, `getDrawingShape` stops at frame content, draggable, not `#nested`); `placeInFrames` (draw end, drag end, transform end, arrow keys, duplicate) moves them by center, `fitFrame` on frame drawn or resized; transformer resizes frames (`setFrameSize`, shapes moved back); arrows link to shapes of frames. Exports hide titles, svg clips.
