# CLAUDE.md

Guide for working on this repository: `@fabwcie/free-drawing`, an infinite canvas drawing library (TypeScript + [Konva](https://konvajs.org/)). Usage: `new Drawer($el, options)` + `import '@fabwcie/free-drawing/style.css'`. User documentation: [packages/free-drawing/README.md](packages/free-drawing/README.md), changelog: [packages/free-drawing/CHANGELOG.md](packages/free-drawing/CHANGELOG.md).

## Repository

Yarn 1 workspaces (root `package.json` is private, `yarn.lock` at root):

- [packages/free-drawing](packages/free-drawing): the library published on npm (`src/`, `tests/`, its vite / vitest / tsconfig / eslint configs, README, CHANGELOG, LICENCE copy). Paths below without a folder are in it (`src/...`, `tests/...`).
- [packages/protocol](packages/protocol) (`@free-drawing/protocol`, private): socket events of live collaboration (`socketEvents`, JS + `index.d.ts`), imported by the library (bundled in its build, dev dependency) and the server.
- [apps/server](apps/server) (`@free-drawing/server`, [README](apps/server/README.md)): TypeScript run with tsx (`src/index.ts`, `createServer` in `src/app.ts` for tests). Express 4: Better Auth accounts (email + password, session cookie) under `/api/auth` (`src/auth.ts`), API of logged in users `/api/me`, `/api/preferences`, `/api/drawings` (`src/api.ts`, own drawings only, 404 for others), socket.io rooms (`src/collaboration.ts`), demo (vite middleware sharing the HTTP server for HMR in development, `apps/web/dist` in production). SQLite of Node (`node:sqlite`) with Kysely (`src/db.ts`): Better Auth tables migrated by its `getMigrations` before creating it, app tables (`drawing`, `preferences`) by a Kysely `Migrator` (add a migration, never change one). Settings from environment (`src/config.ts`). Tests: vitest + supertest on an in-memory database.
- [apps/web](apps/web) (`@free-drawing/web`): demo page, its vite config aliases `@fabwcie/free-drawing` and `@/` to library sources.
- [docs](docs): VitePress site, `yarn doc:changelog` / `doc:get-started` copy the library CHANGELOG / README into it.

## Commands

Run at the root (scripts delegate with `yarn workspace <name> <script>`):

| Command | Purpose |
| --- | --- |
| `yarn dev` | Demo (`apps/web`) with vite (no collaboration server) |
| `yarn serve` | Express + vite middleware + socket.io server on `http://localhost:3000`, demo with live collaboration (meta `collaboration-server` injected in page) |
| `yarn test` / `yarn workspace @fabwcie/free-drawing vitest run tests/x.test.ts` | Tests of the library (vitest, jsdom, jest-canvas-mock), then of the server (`yarn workspace @free-drawing/server test`) |
| `yarn typecheck` | Type check of the library (`src`, `tests`) and the server |
| `yarn workspace @fabwcie/free-drawing tsc --noEmit -p .` | Type check library `src` (its tsconfig only includes `src`) |
| `yarn workspace @fabwcie/free-drawing tsc -p tests` | Type check tests (`tests/tsconfig.json`, needed for the `@/` alias in the IDE) |
| `yarn lint` | ESLint on library `src` and `tests` (no type checking) |
| `yarn build` | Library build in `packages/free-drawing/dist/`: `drawer.js` (es), `drawer.umd.cjs`, `index.d.ts`, `style.css` |
| `yarn build:static` | Demo site in `apps/web/dist/` (deployed by `yarn deploy:static`) |
| `yarn docs` | VitePress docs (`docs/`) |

Git hooks (husky, at root): `commit-msg` runs commitlint (conventional commits), `pre-push` runs `lint` and `test`. CI runs `yarn test` on push / PR to `master`.

## Architecture

- **`Drawer`** ([src/Drawer.ts](packages/free-drawing/src/Drawer.ts)) is the entry point and public API, extends `MicroEvent` (`on` / `off` / `trigger`). It builds a Konva `Stage` with 4 layers, in this order:
  - `bgLayer` (`background`, not listening): background `Rect` named `drawer-background`;
  - `gridLayer` (`grid`, not listening): one `Shape` with a `sceneFunc` drawing the visible grid;
  - `drawLayer` (named `' draw'`, with a leading space: select it with `.draw`): the drawing shapes;
  - `selectionLayer`: transformer, selection rectangle, snapping guides (transient, cleared on load).
- Constructor order matters: options → saved stage or new stage → context menu, settings, zoom, undo / redo → `Toolbar` (widgets) → `Help` (reads toolbar widgets) → active tool → events → optional collaboration.
- **UI components** are plain DOM classes appended to `drawer.$drawerContainer`: `ContextMenu`, `Settings` (dropdown), `LayersPanel`, `SelectionMenu`, `Zoom`, `Position`, `UndoRedo`, `Help` (modal), `CommandPalette` (modal), `Toast`, `Modal` / `ConfirmModal`, overlays. Color choices use [ColorPicker](packages/free-drawing/src/components/ColorPicker/ColorPicker.ts) (palette, custom color input, optional transparent), colors are compared with `normalizeColor` ([utils/color](packages/free-drawing/src/utils/color.ts)). Background color (`fillColor`) only applies to `fillShapes` (rectangle, ellipse), transparent is no fill (`toFill`). Edges (`edges`: 'sharp', 'round' or radius number) only apply to `edgesShapes` (rectangles): `cornerRadius` from `getCornerRadius` ([utils/stroke](packages/free-drawing/src/utils/stroke.ts)), recomputed while drawing, read back with `getEdges` (radius of a shape, shown in radius field). Top left ones go in `$headerContainer` (settings menu, position), bottom ones in `$footerContainer`. `Drawer._update()` runs after each view move or zoom (background, position).
- **Texts** ([src/i18n](packages/free-drawing/src/i18n/)): no hard-coded UI text, every text is `drawer.t(key, params)` (`{name}` placeholders). [en.ts](packages/free-drawing/src/i18n/en.ts) is the reference (`TranslationKey`), `fr`, `es`, `de` are typed `Translations` (a missing key fails type check, `tests/i18n.test.ts` checks placeholders). `drawer.i18n` is created first in the constructor (language: saved `<key>-language` choice, else `language` option, 'auto' = `getLanguage()` of browser), `translations` option overrides texts. Static texts are set with `drawer.i18n.translate((t) => ...)`: run at once and again by `setLanguage`. Content rebuilt from state (layers rows, collaboration dialog, help) re-renders on `drawer.language.change`, or calls `drawer.t` when rendered. Widget titles come from `tools.<id>` keys (unless `title` option).

### Widgets (toolbar tools)

- [BaseWidget](packages/free-drawing/src/components/toolbar/widgets/BaseWidget.ts) is the common base of all widgets: behavior shared by several widgets belongs there (or in an intermediate base such as `ShapeWidget`), not duplicated in each widget. It handles button, shortcut, options (`title`, `shortcut` from `options.widgets`) and lifecycle: `setActive(true)` deactivates the previous widget, then calls `initEvents()` → `updateCursor()` (stage cursor from the `cursor` property) → shows `overlay` (unless `showOverlayOnActive` is false, e.g. selection) → `onActive()`; deactivation calls `removeEvents()` → hides `overlay` → `onDesactive()`.
- Pointer actions (drawing, erasing, selecting, panning) call `startAction()` on pointer down and `endAction()` on pointer up: `inAction` is read by `Drawer._duringAction()` (shortcuts disabled) and UI ignores pointer meanwhile. `clearSelection()` unselects shapes from any widget.
- Register stage events with `this.onStage('mousedown touchstart', handler)`: they are namespaced with the widget id and removed on deactivation. Do not call `stage.on` / `stage.off` directly in widgets.
- [ShapeWidget](packages/free-drawing/src/components/toolbar/widgets/ShapeWidget.ts): drag-to-draw base (`line`, `square` → Rect, `circle` → Ellipse, `arrow`). Implement `createShape(start)` and `updateShape(shape, start, end, constrain)`; shift constrains (square, circle, 45°), also pressed or released during a pointer action (`BaseWidget.onConstrainChange`, used by brush for a straight stroke). With the selection, Shift keeps proportions (transformer `keepRatio` false, Konva keeps them with Shift; true for texts), rotates by 15° (`rotationSnaps` set during transform) and moves along an axis (`dragBoundFunc` set on drag start). One `ShapeOverlay` shared by shape tools.
- [Toolbar](packages/free-drawing/src/components/toolbar/Toolbar.ts) creates widgets from `options.widgets` (list or object of widget options) with the `widgetClasses` map. Adding a widget: class + folder in `src/components/toolbar/widgets/` + `WidgetName` type + `widgetNames` ([constants](packages/free-drawing/src/constants.ts)) + `widgetClasses` + `tools.<id>` title in every language. `tests/basic.test.ts` compares widget folders count with toolbar widgets.
- [SelectWidget](packages/free-drawing/src/components/toolbar/widgets/Select/Select.ts) owns the Konva `Transformer` (others use `getWidget<SelectWidget>('selection')?.transformer`, the widget may be disabled), the selection overlay (`showOverlay`, `hideOverlay`, `clearSelection`), setters applying styles to selected shapes (`_updateSelected`), snapping (drag: `dragmove.snap`; resize: transformer `anchorDragBoundFunc` → `_boundAnchor`, objects first, then `gridAnchorBound` set by drawer while grid is shown), text anchors (side anchors resize text width, corners scale). Selection: `select(shapes)`; a click selects the konva hit shape, or the smallest rectangle / ellipse without background around pointer (`getShapesAt`, Shift toggles, Alt cycles behind); the selection rectangle selects shapes entirely in it; a press in the selection box out of shapes drags the selection (`startDrag`).
- Hit regions are as drawn ([utils/hit](packages/free-drawing/src/utils/hit.ts) `setupHit`, applied by `addShape` and on load): rectangles and ellipses without background are hit on their outline only (hit function, not serialized, kept by collaboration updates).
- [LayersPanel](packages/free-drawing/src/components/LayersPanel/LayersPanel.ts) (`layersPanel` option, button after settings menu, Alt+L): rows of shapes top first, rebuilt on `drawer.change` (deferred during rename or drag), highlighted on `drawer.selection.change` (triggered by `SelectWidget.select` / `clearSelection`), roving tab index per row. Shapes have a `label` attr (name), hidden is `visible(false)`, locked is `listening(false)` (no hit): `select` ignores hidden and locked shapes.
- [SelectionMenu](packages/free-drawing/src/components/SelectionMenu/SelectionMenu.ts): actions next to selection (`selectionMenu` option), updated on selection layer `draw` (selection changed or moved, zoom...) and on drag / transform end, hidden during actions, drags, transforms and text edition. Select shapes from code with `SelectWidget.select(shapes)`.
- [CommandPalette](packages/free-drawing/src/components/CommandPalette/CommandPalette.ts) (`commandPalette` option, menu item, Ctrl+K): combobox search field (focus stays in it, `aria-activedescendant`) and listbox of commands built on each opening by `_getCommands` (only available ones: read only, selection, history, components shown; `checked` for toggles, current tool and language). A new user command (menu item, shortcut) is added there too, with English words in `id` (searched with the translated label).
- [TextWidget](packages/free-drawing/src/components/toolbar/widgets/Text/Text.ts): text nodes, textarea editing (`editTextNode`), double click listened on `drawLayer` (any text is editable), font preload.

### Shapes, options, events

- Add drawing shapes only with `drawer.addShape(shape)` (draggable only with selection tool). Drawing shapes are konva shapes or groups (`DrawingShape`, `shapeName.group`): code reading shape attributes uses `getShapes(node)` ([utils/hit](packages/free-drawing/src/utils/hit.ts)) for shapes of groups. Shapes of groups have ids but are not draggable (moved with their group, except when selected alone with Ctrl+click or layers panel); collaboration, history and files handle top nodes (`getShapeState` keeps children), a changed group is replaced by collaboration. Shapes are identified by names from `shapeName` ([constants](packages/free-drawing/src/constants.ts)), e.g. `shape.hasName(shapeName.text)`.
- Options: `DrawerOptions` ([src/@types/drawer.ts](packages/free-drawing/src/@types/drawer.ts)), defaults in `defaultOptions` ([src/constants.ts](packages/free-drawing/src/constants.ts)). Setters (`setStrokeColor`, `setStrokeWidth`, `setStrokeStyle`, `setEdges`, `setOpacity`, `setTextStyle`) update options, apply to the selection, then trigger `drawer.options.change` with the changed keys. Overlays ([BaseOverlay](packages/free-drawing/src/components/tools/Overlay/BaseOverlay.ts) and subclasses) listen to it to update their fields: overlay buttons only call setters.
- Stroke styles are names (`strokeStyle`: solid, dashed, dotted): the dash is computed from stroke width with `getDash` ([utils/stroke](packages/free-drawing/src/utils/stroke.ts)) and recomputed when width changes, the style of a shape is read from its dash (`getStrokeStyle`).
- After any drawing modification, call `drawer.stage.fire('change')`: it saves to localStorage (`autoSave`), adds a history state and triggers `drawer.change` event. Shape drags are listened on `drawLayer` (`dragend.change`).
- Konva listeners on layers are namespaced (`.grid`, `.snap`, `.change`, `.edit`) so they can be removed separately.
- Files and links ([utils/drawingFile](packages/free-drawing/src/utils/drawingFile.ts)): `.freedrawing` JSON (`DrawingFile`: background, shapes states), validated by `parseDrawingFile` (only drawing shape classes, files and links come from anyone), links put compressed drawing in hash `#<drawer id>=` (loaded by `_loadFromLink`).
- Export ([utils/export](packages/free-drawing/src/utils/export.ts), [ExportModal](packages/free-drawing/src/components/ExportModal/ExportModal.ts)): png and pdf are rendered by clones of shapes in an offscreen konva stage (`renderCanvas`), svg is written per shape class (`renderSvg`, konva has no svg export), pdf embeds a jpeg (`createPdf`), dark mode transforms colors (`toDarkColor`) so every format is the same.
- Stacking order ([utils/order](packages/free-drawing/src/utils/order.ts)): `drawer.reorderShapes(order)` moves selected shapes (`forward` / `backward` past the next overlapping shape, `front` / `back`), from "Layers" buttons of `BaseOverlay` (shown only for a selection) and Ctrl+Up / Down. Collaboration sends `order` (all ids) in `CHANGE` when the order of known shapes changed (`#synced` keeps the stacking order), received ones are applied with `applyOrder`.
- Linked arrows ([utils/binding](packages/free-drawing/src/utils/binding.ts)): arrows have `startBinding` / `endBinding` attrs (ids of shapes, also of groups) and `startAnchor` / `endAnchor` (side whose middle the end is fixed to, else end on outline aiming at the other end). `ArrowWidget` links ends near a shape (smallest one, `findBindingTarget`, side with `getAnchorAt`) and highlights them with their sides (also on hover); `updateBindings` puts linked ends on sides or outlines (`getAnchorPoints`, `getOutlinePoint`: rectangles and ellipses as drawn, other shapes by box) on drag / transform and first in drawer change handler (before saving), removing links to missing shapes; `unbindMoved` unlinks arrows moved without their shapes (drag start, transform start, arrow keys).
- [History](packages/free-drawing/src/components/tools/UndoRedo/History.ts): states are JSON strings of drawing shapes (Konva `toObject`, without `draggable`), identical states are skipped, `historyLimit` (100) states are kept, restore uses `Node.create` + `addShape`.
- Persistence: full stage JSON in localStorage (`options.localStorageKey`, tool in `<key>-tool`). `_loadSavedStage` ignores invalid data; on load the grid layer is rebuilt and the selection layer cleared. Keep loading compatible with saves of previous versions. With `storage` option (`DrawerStorage`, storage of an app), the stage is not read from localStorage: `loadFromStorage` (on init: `ready`) loads its drawing file and resets history, `save` calls `storage.save` (one at a time, `#saveAgain`), never before the drawing is loaded (`#storageLoaded`). Link and room of the URL are opened after it (`_openFromUrl`).
- App integration: `user` option / `setUser` (id and name of collaboration sessions, else kept in browser), preferences (`getPreferences` / `setPreferences`: theme, language, grid, snapping): code changing one calls `_preferencesChanged()` (one `drawer.preferences.change` event per microtask, only if values changed). Option objects replacing a non object default (`collaboration`, `storage`, `user`) are kept as given by `deepMerge` (class instances keep their methods).
- Drawer events ([MicroEvent](packages/free-drawing/src/utils/MicroEvent.ts) `on` / `off` / `trigger`) are named `drawer.<subject>.<action>`, names in `drawerEvents` ([constants](packages/free-drawing/src/constants.ts)). Names of previous versions (`deprecatedEvents`: `change`, `fd.*`) are mapped to current ones with a warning: keep them working.
- [HotKey](packages/free-drawing/src/utils/HotKey.ts): keydown on `$drawerContainer`; tool shortcuts come from widgets; `mod = ctrlKey || metaKey`; nothing runs while `drawer._duringAction()`.
- Collaboration (`collaboration` option gives the server, sessions started from the menu dialog [CollaborationModal](packages/free-drawing/src/components/CollaborationModal/CollaborationModal.ts), `startCollaboration` or a `#room=<id>&by=<user id>` link): `socket.io-client` and `uqr` (QR code) are loaded with a dynamic import and externalized by the build. Clients `JOIN` a room (server keeps each room drawing, sends `USERS`). Pointers (`POINTER`) and shapes being drawn (`sendLive`, from `BaseWidget.shareLive` and drags / transforms, `CHANGE` with `live`) are sent every 50 ms at most as volatile messages, live changes are applied at once without history; cursors of other users are groups of the selection layer. Rooms have an owner (secret `ownerKey` given by the creator, kept in localStorage) who gives or removes the right to draw (`RIGHTS`, `USERS` with `canEdit`); without it, the drawer is read only (`setReadOnly`: UI entry points modifying drawing are disabled, API methods still work). Only the owner sees the session in the dialog (link, QR code, users, stop), other users only their name. Links and page URL carry the id of the user sharing them (`by`, sent as `invitedBy` on `JOIN`), the server resolves it to a name in `USERS`. [Collaboration](packages/free-drawing/src/components/Collaboration/Collaboration.ts) sends, on each drawer `change`, the shapes changed since last sync (`CHANGE` event: `{ upsert, remove }`, shapes identified by their `id`, given by `addShape`) and merges received ones; received during a pointer action, they are applied when it ends (`_onActionEnd`). Socket event names come from `@free-drawing/protocol`. The server identifies logged in users by their account (id sent by client ignored) and sends `JOINED` (`{ userId }`) to the joining user: `Collaboration.userId` takes it (owner, rights, `getCollaborationLink`). The server ([apps/server/index.mjs](apps/server/index.mjs)) relays changes and keeps the drawing for clients connecting later. Undo / redo fire `change` too.

## Conventions

- TypeScript strict. Files of `src/` are imported with the `@/` alias, never relative paths (ESLint `no-restricted-imports`), also in tests and SCSS `@use` (`@use '@/scss/variables' as *`). Prettier: single quotes, 120 columns, 2 spaces. Short English comments.
- Konva is a peer dependency imported by subpath (`konva/lib/...`); the build externalizes `konva`, `perfect-freehand` and `socket.io-client`.
- Accessibility: create buttons with `createButton` (`type="button"`), name icon buttons with `setLabel` and update toggle buttons with `setPressed` (`active` class + `aria-pressed`, or `aria-checked` for menu items), from [utils/dom](packages/free-drawing/src/utils/dom.ts). Lists of buttons use `arrowNavigation` (toolbar, context menu). `HotKey` listens keydown on `$drawerContainer`: keys handled by a component (menu, dialog) must not propagate to it. New icons need `aria-hidden="true" focusable="false"`.
- Styles: one SCSS file per component, every rule scoped under `.drawer-container` (nothing applies to the host page). Color tokens are CSS custom properties (`--drawer-*`) set on the container from `$themes` (light, dark with `drawer-dark` class, see `Drawer.setTheme`): never use Sass color functions on tokens, add a value to both themes. Dark mode only filters the drawing (`$dark-drawing-filter` on `.konvajs-content` and the text editor), colors of shapes are kept; color swatches use `--swatch-color` / `--swatch-dark-color`. Use tokens of [_variables.scss](packages/free-drawing/src/scss/_variables.scss) (colors, radius, shadows, spaces, font sizes) and mixins of [_mixins.scss](packages/free-drawing/src/scss/_mixins.scss) (`focus-ring`, `surface`, `menu-item`, `swatch`, `picker`, `button-group`) with `@use`, not hard-coded values. Panels receiving pointer use `pointer-events: var(--drawer-pointer-events)` (ignored during pointer actions).
- Icons are SVG files imported with `?raw`. In library mode vite inlines assets in `style.css` (the Ubuntu font is woff2 for that reason).
- Tests: use [tests/helpers.ts](packages/free-drawing/tests/helpers.ts) (`createDrawer` with an isolated localStorage key and no autosave, `keydown`, `fireMouse`, `drag`). jsdom has no hit canvas (mock `stage.getIntersection`), no layout and no `document.fonts`: check rendering, pointer and font behavior in a real browser.
- Working copy files use CRLF (`core.autocrlf=true`).

## Versioning and commits

- Each commit changing the library for its users adds its entry at the top of `packages/free-drawing/CHANGELOG.md` (`## [X.Y.Z](compare link) (date)` then `### Features` / `### Bug Fixes`...), copies it to `docs/changelog.md` (`yarn doc:changelog`) and bumps `version` in `packages/free-drawing/package.json` (major for breaking changes, minor for features, patch otherwise). Each version gets an annotated tag `vX.Y.Z`. Private packages (`@free-drawing/*`) have no changelog.
- Documentation and development changes (docs, CLAUDE.md, tests, tooling, refactoring without visible change) have no changelog entry and no version bump.
- `yarn release` builds, pushes with tags and publishes the current library version from `packages/free-drawing` (no bump).
- Claude: never commit or push. Prepare the code, changelog entry, docs copy and version bump, then propose a short conventional commit message without co-author trailer. Tag versions (`git tag -a vX.Y.Z <commit> -m "vX.Y.Z"`) once the maintainer has committed them.

## Pitfalls

- Server: `node:sqlite` is loaded with `process.getBuiltinModule` (vite 4 of tests does not know this built-in module), Kysely 0.29 migrations are imported from `kysely/migration`. TypeScript 5.9: binary data typed `Uint8Array<ArrayBuffer>` where a `BodyInit` / `BlobPart` is needed.
- `npx tsc` / `npx vitest` from a workspace folder in Git Bash resolve a wrong path: use `yarn workspace <name> <bin>`. Tools whose binary is run from the root (`typescript`, `prettier`, `vitepress`) are root dev dependencies, so the root `.bin` gets the right version.
- Tests run in one shared jsdom document (`threads: false`): close dialogs opened by a test (a shown `Modal` listens keydown on document). A dialog whose drawer left the page releases its document listeners.
- Fonts load when first used: measure or draw texts after `document.fonts.load` (see `TextWidget._loadFonts`). The editing textarea compensates the baseline difference between canvas and CSS (`_baselineOffset`).
- Konva `Transformer` ends a transform on window `mouseup` (capture phase), before the stage `mouseup`: `isTransforming()` is already false there (see `#pressOnTransformer` in `SelectWidget`).
- Grid: one stroke per line. A single path with hundreds of dashed lines is very slow in Chromium.
- `deepMerge` does not merge arrays: `widgets` option is replaced, not merged. Never mutate `defaultOptions` (setters replace nested objects such as `textStyle`).
- `GroupWidget` (group of toolbar widgets) is not used yet, unrelated to groups of shapes (see [TODO.md](TODO.md)).
